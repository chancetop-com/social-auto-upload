# 账号别名与登录态校验

Type: grilling
Status: resolved
Blocked by: 01, 03
Assignee: Codex（本会话）

## Question

账号别名只用于定位和管理浏览器资料，不固定对应某个真实账号。业务流程在未登录或登录失效时结束，用户单独登录后重新发起流程；怎样据此退出旧身份约束，保留必要的登录态与显式目标校验？

- Instagram 不继承旧 Cookie JSON 中的账号 ID；新 Profile 怎样取得当次真实账号信息？
- 大鱼号、知乎、雪球的旧 `.identity.json` 不再作为换号限制，何时清理，怎样与 Cookie 清理及失败恢复衔接？
- 同一别名的 Chrome / Chromium 可以登录不同真实账号；Profile 归属元数据、登录状态与实际平台主体怎样区分？
- 怎样移除历史账号绑定和为防中途换号而增加的前后身份比较，同时保留指定发布目标、历史结果的作品与作者核对？
- 先前决策中要求保留和共享真实账号绑定的条款怎样随本次用户修正退出，并保持未迁移平台、托管流程及发布结果契约的边界？

回答应给出各例外平台的当次身份来源、旧文件处理表及清理前置条件。本票不实现迁移工具，也不扩大真实回归平台范围。

## Answer

### 别名、Profile 与真实账号

- `--account` 是账号别名，用于定位浏览器资料、日志和上报，不是对平台真实账号的声明。同一别名重新登录成任何账号均可；不要求保留原主体，不新增重绑命令，也不要求换号必须另建别名。
- 目录仍按平台、原始别名、浏览器种类定位。同一别名的 Chrome 与 Chromium 可登录不同真实账号，各自保存和核验当前登录态，不共享账号 ID 或绑定记录。
- 平台、原始别名、浏览器种类的目录归属校验继续保留，防止路径越界或别名碰撞。这种资料归属与平台真实账号不同，不能因现场账号变化而报目录归属冲突。
- 不创建替代旧文件的长期真实账号绑定；不做绑定迁移、绑定丢失判定、换号暂停状态或跨 Profile 的绑定同步。已有登录确认状态只表示该 Profile 完成过相应初始化，不证明现在仍登录，更不固定真实账号。
- reset-profile 仍只清理明确指定的 Profile 及其专属状态，保留别名归属、另一种类 Profile 和历史发布结果。重新 login 可选择任意真实账号；不自动退出站点账号、清空其他 Profile 或续跑发布。

### 各平台的身份来源与旧文件处理

| 平台 | 已迁移本地流程的身份来源与核验 | 退出的旧约束 |
| --- | --- | --- |
| Instagram | 核验当前 Profile 的平台登录证据；发布、结果记录或 verify/delete 需要账号字段时，从当前会话取得有效的 `ds_user_id` 等信息。 | 不读取旧 Cookie JSON 提取 ID，不与历史账号或本次起始快照比较，不导出新的 Cookie JSON 或身份旁文件。 |
| 大鱼号 | 平台操作、结果记录、显式 `--expected-name` 或作品验证需要时，从当前后台页面取得 `wmid/name` 并校验字段格式。 | 不再读写 `<platform>_<别名>.identity.json`，移除仅为防止换号而比较发布前后 `wmid` 的检查。 |
| 雪球 | 平台操作、结果记录、显式期望名称或作品验证需要时，从当前页面或响应取得 `uid/name` 并校验字段格式；保留发布结果本身的成功证据。 | 不再读写旧身份旁文件，不将历史登录或本次起始 `uid` 设为防错配约束；响应中的作者信息按实际结果记录。 |
| 知乎 | 平台操作、结果记录或历史作品验证需要时，从当前页面取得 `name/avatar_path`；不新增永久 ID 探测。 | 不再读写旧身份旁文件，不用名称/头像的前后快照检测换号；不因历史别名记录而拒绝改名、换头像或换账号。 |
| Facebook / Facebook Page | 保留现有当次 `owner_id`、Page 名称/ID、作品信息等目标校验；Page 未显式指定时仍按原流程使用当前主体。 | 不增加登录管理员或 Page 与别名之间的长期绑定。Facebook 与 Facebook Page 目录仍独立。 |
| 其他迁移平台 | 保留现有登录证据及当次操作的目标校验。 | 不为本次迁移新增长期真实账号绑定，不要求原先没有主体检查的平台补建身份体系。 |

当前浏览器会话中的身份字段可以用于上述操作；“不读旧 Cookie JSON”不等于禁止读取当前浏览器的 Cookie。只取业务所需字段，不复制完整 Cookie、token 或登录态到资料元数据。身份信息可继续出现在既有发布结果中，因为它描述那次操作，不约束别名以后登录谁。字段格式校验只服务于实际需要该字段的操作；不能把已淘汰的防错配检查改名为“身份提取成功”后继续作为所有命令的前置条件。

### 登录失效、业务流程与历史作品

- login/check 核验所选 Profile 当前是否登录；平台正向登录证据本身需要读取账号字段时保留必要读取，但不额外比较历史账号、另一浏览器种类或本次起始账号。
- 发布等业务流程使用所选 Profile 当前的登录态。开始时未登录或过程中明确登录失效，均结束本次流程；不等待用户在原流程里重新登录、自动恢复登录或登录后继续原发布。用户另行执行 login 后，再次业务调用是新流程，可以使用任意真实账号。
- 不建立本次起始账号快照作为防换号门槛，也不保留仅用于检查流程前后账号是否一致的比较。自动化流程不提供中途登录或切换账号的分支；不为人工在运行中改变浏览器账号增设账号一致性机制。
- 显式发布目标和期望值继续有效，例如 `--page`、`--expected-name`。别名可以换号，不代表这些本次请求参数可以忽略。
- verify/delete 等针对已有作品的操作继续核对作品 ID、作者、Page 或其他原始结果信息；原流程要求当前会话主体与作品作者一致时仍核对。不能用当前别名下的新账号覆盖历史作品作者，不能因为别名相同就跳过作品身份检查。
- 历史发布结果保持原样，不重写为新登录账号，也不因旧身份文件清理而删除。知乎旧结果仍只有名称和头像路径；按既有证据验证，不能把这种弱标识宣称为永久 ID。证据不符或不足时按原验证失败契约处理，不自动修改旧结果。
- 显式目标不符或历史作品核验失败按原操作故障契约处理，不永久封锁别名或 Profile。明确未登录仍为 `10`，实际必需的字段提取、网络或页面结构故障为 `1`，不误报登录失效。提交后继续保持既有 `publish_attempted`、发布结果未知及退出语义，人工重新登录也不解除禁止自动重发的约束；可能已提交时仍须先核查原作品。

### 一次性清理旧 Cookie 与旧身份文件

本节仅适用于迁移阶段。完成后删除旧文件识别、重启复验、清理与重试代码及临时入口；正式运行不再探测旧 Cookie 或旧身份旁文件，不保留延迟到未来 login 执行的迁移分支。

- 按迁移平台、当前别名明确定位旧 Cookie JSON；大鱼号、知乎、雪球同时定位原 Cookie 路径对应的 `.identity.json`。不扫描后缀后批量删除，不处理其他别名、平台、历史结果或托管资料。
- 已迁移流程从开始即停止读取旧 Cookie 和旧身份文件。旧文件缺失、损坏、记录着其他账号均不阻止在新 Profile 登录；不为清理而解析其身份内容。安全路径无法确定、路径归属异常或文件操作失败须明确报告。
- 一次性迁移中，当对应旧 Cookie **或旧身份文件任一仍存在**时，迁移编排必须完成平台正向登录核验、正常关闭、同目录同配置重启复验并再次正常关闭，才可清理这些旧文件。重启复验使用当前 Profile，不与旧文件的账号比较；删除不创建备份。
- 失败、取消、明确未登录、无法可靠核验或关闭失败时，保留尚未清理的旧文件；其存在不构成可用登录态。清理失败退出 `1` 并说明剩余目标，保留已建立的 Profile；在迁移阶段复验并重试剩余清理，不重新绑定账号，不回退旧文件，不把清理重试延迟为永久 login 行为。
- 清理多个文件部分成功时不尝试恢复已删除文件；重试只处理剩余目标。文件已经不存在视为已清理。同别名两种浏览器并行通过验收后清理同一旧文件也按此规则收敛，不为不存在的共享真实账号绑定增加互斥；Profile 本身的独占规则不变。
- reset-profile 不顺带清理这些旧文件；旧资料退出仍以上述一次性迁移验收为前提。迁移阶段只有旧身份文件残留时同样适用；迁移完成后的命令不再包含相关处理。

### 分批实施与验收边界

- 本票取代前置决策中“跨浏览器共享真实账号绑定”“重建后不得换号”以及“旧身份文件永久保留”的要求；具体规则以本票为唯一详细来源。可读别名目录、安全归属检查、浏览器种类隔离和生命周期规则仍有效。
- 仅在对应平台迁移批次切换本地流程；未迁移平台继续现有代码行为。托管模式的身份来源、校验和文件行为不变，不因本地移除旁文件而改写托管逻辑。
- 离线验收须覆盖：同别名 A→B 重新登录、两种浏览器分别登录不同主体、未登录/登录失效结束当前业务且不等待登录后续跑、旧身份文件缺失/损坏不阻断新登录、无历史/起始账号快照防错配门槛、指定目标与历史作品核验、未迁移/托管行为及发布结果契约。旧文件清理、部分失败和仅旁文件残留在一次性迁移执行前验证；迁移后删除专用实现和测试，最终验证重新出现的旧文件不会被日常命令读取、清理或触发额外重启。
- 真实回归范围仍为 TikTok、Rednote、Instagram、小红书，不因本票要求额外平台账号。实现与测试清单交由[分批接入的共享边界与平台例外](./04-platform-integration-boundaries.md)展开；本会话仅修改决策资料和术语，没有改实现或处理真实账号文件。
