# 06 — 能力预检与失败语义

Status: resolved
Type: grilling
Blocked by: 01, 03, 04

## Question

发布前是否读取页面上的账号级可用选项并校验？需要确定：

1. 是否在填写前抓取隐私选项、互动开关可用性、视频时长上限，做一次能力预检。
2. 请求的选项不可用时：fail-fast、回退到默认值，还是继续并警告？
3. 退出码是否沿用 `0/1/2/10/130`；是否需要为“参数不被账号支持”新增退出码。
4. 每一步的超时：页面加载、上传、表单填写、发布、封面处理。
5. 发布点击后结果未知（超时/断连）如何处理：报告未知、禁止自动重发、如何核查。
6. 登录失效、验证码、2FA 与账号能力不足如何区分。

## Answer

### 1. 能力预检：不做

沿用现有“设置 → 回读 → 发布按钮状态”的模式，不单列能力预检：

- 不读取隐私下拉的可用选项矩阵。
- 不读取互动/品牌/AI 控件的 `disabled` 状态。
- 不读取视频时长上限。
- 规格术语统一为“设置后回读校验”，不再出现“能力预检”。

唯一例外是 `upload-note` 的 Photos tab 探测：它决定文件进哪个 input（否则会静默落到视频 input），属于路径选择，不属于能力预检。找不到 Photos 入口时，在选文件前报错并退出 1。

代价（明确接受）：账号不支持的隐私级别或品牌组合，要等文件上传完成、进入表单阶段才会失败，失败前已经消耗上传时间。

### 2. 不可用项：以回读到的最终状态判定

只比较“请求状态”与“回读到的最终状态”：

- 一致 → 成功。即使控件置灰、账号级已禁止，也不额外报错。例：账号已禁用评论 + `--no-comments` → 成功。
- 不一致 → 失败，不点击发布，退出 1。stderr 必须写明选项名、请求值、实际值。
- 不回退到页面默认值，不“警告后继续”。
- 与 05 的“显式传参 → 设置后回读；不一致视为失败，不发布”一致。

### 3. 退出码

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 运行失败，含账号能力不支持、网络/5xx/超时、页面结构异常 |
| `2` | 用法错误与本地参数校验失败 |
| `9` | **发布结果未知**（新增，仅此一种语义） |
| `10` | 需要人工登录（登录页/验证码/2FA 跳转） |
| `130` | 用户中断（Python 默认，不在 `sau_cli` 显式映射） |

实现落点：

- `utils/errors.py` 新增 `PublishResultUnknownError`。
- `sau_cli.main` 在 `LoginRequiredError` 分支之后、通用 `Exception` 之前映射为 `9`。
- `upload-video` 与 `upload-note` 共用同一映射。
- README、`docs/CLI.md`、调度侧退出码契约同步加入 `9`，并注明“禁止自动重发”。

账号能力不支持**不新增**退出码，仍为 `1`；与 Multilogin 规格“启动类失败不新增退出码”的取向一致。

### 4. 超时：沿用现状，不改行为

规格只把现有值写成常量表，不新增单步上限；新增表单步骤使用 Playwright 默认 30s。

| 环节 | 值 | 现状 |
| --- | --- | --- |
| 登录检测总预算 | 20s | `TIKTOK_LOGIN_CHECK_TIMEOUT_MS` |
| 登录检测内部入口轮询 | 5s | `TIKTOK_ENTRY_WAIT_MS` |
| 进入上传页 URL | 10s | `page.wait_for_url` |
| iframe / `div.upload-container` 出现 | 10s | `wait_for_selector` |
| 上传按钮可见 | 30s | Playwright 默认 |
| 发布循环总预算 | 15 分钟 | `TIKTOK_PUBLISH_TIMEOUT_SECONDS` |
| 点击发布后等成功页 | 单次 3s，失败 0.5s 后重试，直到总预算 | `click_publish` |
| 封面上传后 | 固定 3s | 现有等待 |
| 表单输入之间 | 固定 1s | 现有等待 |
| 新增隐私/开关/AI/品牌步骤 | 每次操作 Playwright 默认 30s，步骤之间沿用 1s | 新代码按现有风格 |

TikTok 已仅支持 Multilogin 模式，15 分钟总预算对两条路径都生效。

### 5. 发布结果未知（退出码 9）

定义：**点击动作已经发出 + 没有观察到成功页 + 没有命中登录/验证码跳转**。

判定与行为：

1. 跟踪 `publish_clicked`：点击调用已发出且未抛异常即置真。
2. 到达 `https://www.tiktok.com/tiktokstudio/content` → 成功。之后仍按现状调用 `get_last_video_id`；**保持现状**：查询失败会让整次运行退出 1，这是已记录的已知风险，本 effort 不改。
3. 总预算耗尽但从未点击发布按钮 → 普通失败，退出 1，消息说明“未发布”。
4. 已点击、但到总预算仍未到成功页，且未命中登录 URL → `PublishResultUnknownError`，退出 9。
5. 已点击后页面/上下文关闭、CDP 断开、停在表单报错、点击落在禁用按钮上空操作 → 同样按第 4 条处理，不再吞异常空转到预算耗尽。

覆盖的具体情况：

- 点击已发出，但处理慢/重定向丢失，15 分钟预算耗尽。
- 点击后 Profile 被关闭、浏览器崩溃、CDP 断开。
- 点击后页面停在表单并显示错误/弹层，URL 不变。
- 点击时按钮实际禁用，点击为空操作。

不算未知、仍按既有路径处理：

- 从未点到发布按钮 → 未发布，退出 1。
- 点击后 URL 命中 `/login`、`captcha`、`verify`、`two-factor`、`2fa` → 退出 10。

调度侧契约：

- 收到 `9`：**禁止自动重发**。可能已经发出。
- 人工核验：打开 TikTok Studio → Content / Posts 列表，按标题与发布时间核对；已存在则不要重发，不存在才可人工重试。
- 机器信号就是退出码 `9`；stderr 只写中文说明与核验路径，不额外定义字符串标记。

### 6. 登录 / 验证码 / 2FA / 能力不足：沿用现状

- 发布前 `is_logged_in`：`/login` 路径或登录表单 → `False`（退出 10）；无法识别页面结构 → 抛异常（退出 1）。
- 发布过程中 `_raise_if_login_required`：只看 `page.url` 的 path，命中 `/login`、`captcha`、`verify`、`two-factor`、`2fa` → `LoginRequiredError`（退出 10）。每轮上传/发布循环继续检查。
- 内嵌验证码/2FA 如果不跳 URL → 不识别，落到普通失败退出 1。这是**已知盲区**，本 effort 不新增 DOM 检测，规格需记录。
- 账号能力不支持 → 退出 1，消息写明请求值与实际值。
- 网络错误、5xx、超时、结构异常 → 退出 1。

### 对下游工单的影响

- **07 — 测试与验收策略**：需覆盖退出码 `9`、“未发布 vs 结果未知”的分支、回读最终状态（含置灰但目标已满足）、超时常量；未知结果不得自动重发要有断言。
- **08 — 汇总实施规格**：退出码表加入 `9`；对照矩阵明确“无能力预检，只有设置后回读”；记录内嵌验证码盲区与“取 video_id 失败仍退 1”的已知风险。
- **09 — 共用流程与扩展点**：发布循环需暴露 `publish_clicked` 状态；新增步骤函数不得吞掉异常；`PublishResultUnknownError` 只能由发布阶段抛出。
