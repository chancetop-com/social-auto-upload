## Answer

规格已写入 [`../spec.md`](../spec.md)，覆盖工单要求的 7 个部分：

1. 目标与非目标、术语（含设置后回读 / 发布结果未知 / Photos tab）、通道约束、代码基线事实。
2. “API 能力 ↔ 浏览器实现”矩阵，逐项标注可行 / 条件可行 / 不可行 / 不做与置信度。
3. `upload-video` 新参数、`upload-note` 全量参数、默认值、互斥与组合规则、本地校验。
4. 视频与图片两条 UI 路径：9 步模板骨架、逐步候选选择器、等待点与作用域。
5. 设置后回读规则、退出码（含新增 `9`）、结果未知判定、登录盲区、超时常量表。
6. 三层测试策略（7 组离线 + opt-in 冒烟 + 人工验收）、现有测试改动、漂移刷新流程。
7. 部署前提、7 个实施阶段、文档/Skill 变更清单、风险与回滚。

本工单新定的三项：

- **选择器降级策略**：每步有序候选列表；`data-e2e` → role/text → 文本；不做跨步骤通用兜底；失败消息含控件名、候选、URL、阶段；设置与回读共用同一候选列表。
- **`--json` 不进入 v1**：机器信号只有退出码 + stderr；如后续需要另立 effort。
- **图片帖 AIGC/品牌未渲染时**：显式请求即按回读失败退出 `1`，不静默忽略、不回退默认。

仍然只能实施时实测的事实项（不是未决决策，已写进 spec §11.1 并给出兜底）：图片帖 AIGC/品牌是否渲染、图片帖表单精确 DOM、Photos tab 灰度范围、私有账号文案、封面服务端接受度、35×50 MB 的 15 分钟预算。

本工单只写规格，未改生产代码、未执行测试。
