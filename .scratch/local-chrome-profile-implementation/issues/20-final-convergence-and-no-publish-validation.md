# 20: 完成全入口收口与四平台真实验收

**What to build:** 所有正式本地浏览器动作都使用 Profile，用户能按文档选择并准备浏览器；四个指定平台用已有账号完成真实登录、关闭重开检查和不发布模式验证，交付清晰区分离线、浏览器与平台证据的最终记录。

**Blocked by:** [19：执行一次性旧资料迁移并删除临时实现](./19-one-time-legacy-migration.md)

**Status:** ready-for-agent

**批次：** 最终交付

**依据：** [原始规格](../../local-chrome-profile/spec.md)；[实施顺序与共同约束](../README.md)。

- [ ] 按正式 CLI 注册动作逐一核对全部五批平台及可达启动链，覆盖独立 check、内部预检、视频/图文/文章和已有 verify/delete；确认临时新旧分流、旧 JSON 预检/恢复/导出和旧身份防错配逻辑已退出正式范围。
- [ ] 结合 19 的执行与删除记录，确认不再存在本次新增的一次性迁移入口、识别、重启复验、清理/重试或停用分支；用正常 login/check/业务的外部行为验证旧文件重新出现仍被忽略，普通 login 不额外重启。
- [ ] 按实际剩余引用核对辅助资源与打包内容，只删除已无调用方需要的资源；保留 Bilibili biliup 和正式 CLI 不可达历史入口仍实际需要的内容，不以这些范围外调用方为由保留本次临时迁移实现。
- [ ] 最终基础安装不无条件下载或检查 Chrome/Chromium；本地仅要求实际选定来源，托管两者都不要求。系统 Chrome 缺失时说明由用户依 Google 官方指引安装，项目不自动安装/更新，也不把 Patchright 安装 Chrome 作为默认路线。
- [ ] README 与安装指南完整呈现两条独立的按需 CI 安装路线：已有研究中的 Ubuntu 24.04 x64 官方 Chrome amd64 DEB，以及项目固定 Patchright 配套完整 Chromium；说明各自系统依赖、无显示有头运行的 Xvfb、项目版本/缓存一致性及兼容自定义 binary 复用。
- [ ] Chromium 文档提供可选的 uv run patchright install --no-shell chromium，说明普通 Chromium 安装可用、仅 headless shell 不满足运行契约；安装示例不冒充已执行结果，不新增 workflow 或 CI 验收系统。
- [ ] 收口配置示例、各平台 CLI/skill、登录说明、Agent Bootstrap、运行依赖说明及本地模式术语，使其符合最终已实现状态；安装完成、浏览器能启动和平台已登录分别表述，不覆盖用户既有 headless=True。
- [ ] 汇总各批相关离线回归，并补足最终入口清单暴露的实际缺口，验证托管除批准 headless 来源外的动作路由、所有权、日志和错误契约保持；无新改动或疑点不无理由重复完整测试矩阵。
- [ ] 核对 02 的真实 Chrome/Chromium、有头/无头、自定义路径、持久化与匿名隔离证据；共享能力后续改变时补跑受影响项。未运行的环境明确列出，模拟测试不替代真实浏览器证明。
- [ ] 由实施 Agent 在执行时落实用户已有 TikTok、Rednote、Instagram、小红书账号和素材，以默认 Chrome 有头路径分别执行 login、正常关闭后重开 check，以及正式视频/图文发布前流程；不把四平台真实回归交给用户手动完成。
- [ ] 真实视频/图文命令全部显式使用 no-publish，并核对参数传递和实际停止点；任何入口保护缺失都先修复并离线证明，再运行真实流程。保留素材上传、编辑和发布就绪检查后停止的语义，不能靠提前跳过这些步骤充当验收。
- [ ] 不实际提交发布、不删除真实作品，也不为验证作品管理先发帖；verify/delete、提交后异常和结果观察由相关离线回归覆盖。其他平台与托管不要求新真实账号，不扩展全浏览器配置的真实平台矩阵。
- [ ] 最终报告分列离线结果、浏览器实测、四平台不发布模式结果，记录配置、命令、实际停止点和具体失败/阻塞；说明真实素材上传可能留下临时素材或草稿，成功只证明提交前流程，不证明实际发布、not-before 等待、发布后验证或防封禁。
- [ ] 只有五批接入、一次性迁移执行与临时代码删除、文档和约定验证都落实才标记整体完成；未执行或阻塞项明确保留，不以离线替身或安装说明代替实际证据。
