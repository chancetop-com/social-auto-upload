# 01: 安全定位、占用与重建本地 Profile

**What to build:** 用户可以通过明确指定平台、账号别名和浏览器种类的 reset-profile 安全清空一个本地浏览器 Profile，无需安装或启动浏览器；安全定位和 Profile 占用能力也供后续登录与业务会话复用。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**批次：** 第一批

**依据：** [原始规格](../../local-chrome-profile/spec.md)；[实施顺序与共同约束](../README.md)。

- [ ] 提供 sau <平台> reset-profile --account <别名> --browser-kind chrome|chromium 的完整 CLI 行为；本票先为第一批平台开放，后续平台随各自接入票开放，Bilibili 不提供入口。未迁移平台的已有动作继续按原行为运行。
- [ ] Profile 使用项目专用根，依正式平台、原始账号别名、实际浏览器种类隔离，以浏览器种类叶子目录作为 user data directory；不使用日常浏览器资料、父账号目录或浏览器内部 Default 目录，整个资料根排除版本控制。
- [ ] 别名保持原值与可读性，不裁剪、改大小写、Unicode 归一化、哈希化或转义；拒绝空白名称、路径分隔符、点目录及越界输入，文件系统不支持时明确失败。大小写或 Unicode 等价路径碰撞不得合并账号资料。
- [ ] 在互斥保护下安全创建、读取和校验平台、原始别名及种类归属；已有目录元数据缺失、损坏或冲突时拒绝认领。元数据不包含凭据副本或永久真实账号绑定，父级别名归属可供两种浏览器安全共用。
- [ ] 针对实际解析目录建立非等待式跨进程互斥；同 Profile 占用立即以 1 退出，不同 Profile（包括同别名两种浏览器）可并行，等价路径不能绕过占用。PID、时间戳和诊断文件存在不代替活锁判定。
- [ ] 锁与可重建资料分离，重建不删除自身互斥保护；残留诊断文件不永久阻断使用。检测到外部浏览器占用或无法安全确认时给出有依据的故障，不删除 singleton 锁、不终止或接管外部浏览器。
- [ ] 重建目标仅由显式 browser-kind 决定，不读取浏览器选择、可执行文件配置或安装状态来推导，不启动浏览器、不执行产品识别；托管模式拒绝此动作，且不调用 provider。
- [ ] 归属、路径与占用检查通过后，只删除目标种类叶子目录和专属状态；保留父级别名归属、另一种类、其他别名、历史发布结果及旧 Cookie/身份资料。
- [ ] 显式命令即清除意图，不增加交互确认或备份；显示目标和结果。目标不存在视为已清空，成功退出 0 并提示 login，不启动登录、不续跑业务、不创建看似有效的 Profile。
- [ ] 部分删除失败退出 1，报告未完成状态；残缺资料不能被后续会话当作有效 Profile，修复后可重跑同一显式命令。重建不构成重新发布旧任务的依据。
- [ ] 从正式 CLI 验证目标选择、非法参数、路径/归属冲突、无需 binary、托管拒绝、已不存在、部分失败和保留范围；使用临时目录及两个真实子进程，通过同一公开 Profile 取得入口验证争用、释放、不同 Profile 并行和残留诊断文件，不新增仅供测试的锁接口。
- [ ] 同步本批重建命令说明与交付记录，列出测试命令、实际结果及尚未迁移平台；本票只验证重建和占用，浏览器启动及持久化实测由 02 完成。
