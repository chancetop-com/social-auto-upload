# 哪些证据足以验收比特浏览器托管模式

Label: wayfinder:grilling
Type: grilling
Status: resolved
Assignee: LukeChen
Blocked by: 06

## Question

针对七个平台的二十个入口，哪些行为可由离线契约测试证明，哪些必须在真实桌面客户端上观察？为已登录窗口的检查、发布前停止、同窗口跨平台并行、同平台占用和最后退出定下可判定的成功标准，并明确如何记录尚未经真机验证的能力。

按[哪些客户端版本和配置属于首版支持范围](06-client-compatibility.md)选择测试环境。验收用例应可分别追溯至[调用方怎样选中比特浏览器并定位已有窗口](02-activation.md)、[冷启动、加入和最后退出时怎样识别同一个窗口](03-shared-window.md)和[窗口启动选项和 API 错误怎样映射到 CLI 契约](04-failure-contract.md)。

## Answer

2026-11-22，用户确认分两步验收。20 个入口的离线契约测试通过后即可交付实现。各真机用例取得对应的比特浏览器实测记录后，再逐项标记「真机通过」。当前用户没有比特浏览器账号，以下真机用例均为「待验证」。本轮只确定验收标准。

### 实现交付所需的离线证据

- 从正式 CLI 入口逐项运行 7 个 `check`、7 个 `upload-video` 和 6 个 `upload-note`。用模拟的比特浏览器 Local API 和受控平台页面核对选中的提供方、传给 API 的窗口 ID、页面归属、命令输出和退出码。凭据冲突、缺少窗口 ID 等用例须在接触窗口前结束。[调用方怎样选中比特浏览器并定位已有窗口](02-activation.md) · [命令矩阵](../../../docs/CLI.md#平台支持范围)
- 小红书、Rednote、TikTok 和 Instagram 的 8 个发布入口覆盖 `--no-publish`，检查素材与编辑器就绪、退出码为 `0`、最终提交次数为零。Facebook 个人、Facebook Page 和 YouTube 的 5 个发布入口没有这个开关，在受控页面走各自的发布流程，观察提交次数及结果。[现有 CLI 契约](../../../docs/CLI.md#平台支持范围)
- 用两个独立 CLI 进程验证冷启动、加入和退出的顺序及打开、关闭次数。注入启动回包丢失、连接地址不一致和清理失败，核对同行页面及原命令结果。分别检查 HTTP `429`、业务错误、平台登录失效和发布结果未知的退出码与诊断。[冷启动、加入和最后退出时怎样识别同一个窗口](03-shared-window.md) · [窗口启动选项和 API 错误怎样映射到 CLI 契约](04-failure-contract.md)

### 有账号后的真机通过标准

| 用例 | 应采到的证据 |
| --- | --- |
| 七个平台各检查一次 | 对每个平台，选择已在桌面端登录该平台的窗口，以复制的 ID 运行 `check`。命令复用窗口中的登录态，stdout 仅有 `valid`，退出码为 `0`。 |
| 两个平台并行到达发布前停止点 | 对同一个已登录两平台的窗口，同时运行 TikTok `upload-video --no-publish` 和 Instagram `upload-note --no-publish`。在两张不同的编辑页读回各自的草稿标记。TikTok 输出发布前检查通过的摘要，Instagram 结果为 `prepared`，两条命令均退出 `0`，最终提交次数均为零。 |
| 同平台占用 | 在其中一条发布命令仍占用窗口时，再运行同平台的 `check`。它在打开平台页面前提示该平台被占用并退出 `1`，原命令可继续编辑。 |
| 冷启动和加入桌面已开的窗口 | 从窗口关闭和桌面预开两种状态分别运行上述并行用例。冷启动合计一次 `/browser/open`，从打开响应和随后查到的调试端口识别到同一浏览器实例。桌面预开时两条命令合计零次打开，进入前在桌面原标签留下可回读的标记。 |
| 首条与末条退出 | 首条退出后，其页面已清理，关闭请求为零，同行能在原编辑页追加并回读文字。桌面预开场景还应读回原标签的标记。末条退出时，对同一窗口 ID 恰有一次 `/browser/close`。分别记录关闭回包、旧进程退出和原调试端口消失的时刻。再次冷启动前按共享约定等待至少 5 秒并确认旧进程已退出。 |

每次实测记录客户端及 Chromium 内核版本、命令与退出顺序，并附脱敏的 API 计数、页面标记和最终窗口状态。遇到客户端限流时，记录实际 HTTP 状态和业务响应。尚未观察到的响应形态继续标「待验证」。其余发布入口保留各自的离线结果。实测记录可沿用 AdsPower 的时间线格式。[哪些客户端版本和配置属于首版支持范围](06-client-compatibility.md) · [AdsPower 实机记录](../../managed-profile-sharing/research/14-macos.md)
