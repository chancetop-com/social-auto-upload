# 冷启动、加入和最后退出时怎样识别同一个窗口

Label: wayfinder:grilling
Type: grilling
Status: resolved
Assignee: LukeChen
Blocked by: 01

## Question

用户先在桌面打开窗口，Instagram 与 TikTok 两条 CLI 先后加入，再按不同顺序离开。比特浏览器提供的哪些信号足以找到当前实例和 CDP 端点、复用已有上下文，并让最后一条命令归还窗口？如果桌面端中途关闭并重开窗口、首个命令在启动时中断，或无法确认当前实例，应怎样保留现有共享规则和各命令的结果？

结合[共享会话接口](../../../utils/managed_browser.py)里的 `observe`、`resource_identity` 和 `asynchronous_stop`，对照[现行会话规则](../../managed-profile-sharing/spec.md)与[比特浏览器的本机 API 能力](01-local-api.md)。

## Answer

用户决定与 AdsPower 保持一致。加入时核对浏览器实例，最后一条已加入的命令直接按窗口 ID 关闭整个窗口。关闭前不再查询实例。如果旧命令尚在运行，用户从桌面关闭并重开同一 ID，旧命令最后退出时可能关掉新窗口。[AdsPower 共享协调](../../../utils/managed_sharing.py)

| 场景 | 比特浏览器的约定 |
| --- | --- |
| 两条命令同时冷启动 | 同一系统用户按提供方和窗口 ID 共用锁，`resource_identity` 核对规范化的 Local API 地址。同平台的第二条命令在开页前以 `1` 退出。不同平台串行核对窗口状态，确认空闲且没有待确认的启动时，合计只发一次 `/browser/open`，从响应的 `data.ws` 取得浏览器级连接。 |
| 桌面已开，或另一条命令正使用该窗口 | `observe` 按窗口 ID 核对存活进程，通过 `/browser/ports` 查该 ID 的调试端口，再从 CDP 的 `/json/version` 取得浏览器级 WebSocket 地址。已有同行时，地址摘要必须与共享记录一致。查到进程却取不到可用连接、状态矛盾或摘要不符时，在开页前报错。连接成功后复用唯一的现有上下文，各命令另开自己的标签页。 |
| 启动中断或回包丢失 | 发出打开请求前先记录正在启动。后继命令查到该窗口已运行且可连接时，加入并另开新页。若仍无法确认上次启动已结束，即使暂时没有调试端口，也报告启动结果未明，保留现场，不补发打开或关闭请求。 |
| 两条命令先后退出 | 先离开的命令只清理自己的页面并断开连接，同行草稿和桌面标签仍可用。最后一条直接调用一次 `/browser/close` 并传入同一窗口 ID。清理或关闭失败只告警，各命令保留自己的发布结果和退出码。 |
| 全部 CLI 已被强杀 | 若桌面保留了原窗口，或已重开同一 ID，下一条命令重新查询并连接当前实例，在新标签页开始。已落盘结果保留，恢复流程不续点旧草稿。 |

比特浏览器的关闭回包与进程退出分开处理。提供方使用共享层的异步停止语义（`asynchronous_stop`）。再次冷启动前遵守官方关闭后等待 5 秒的要求，并确认旧进程已退出。停止状态在共享层的有界等待内仍无法确认时，向新命令报告原因。该检查发生在重新启动前。[本机 API 研究笔记](../research/01-local-api.md)

比特浏览器的真机验收还需核对冷启动返回的地址与随后查询到的地址能否稳定识别同一次运行，并记录关闭回包后进程和端口消失的时机。AdsPower 已有冷启动、桌面预开和全部 CLI 被强杀后恢复的实机记录。[哪些证据足以验收比特浏览器托管模式](05-acceptance.md) · [AdsPower 实机记录](../../managed-profile-sharing/research/14-macos.md)
