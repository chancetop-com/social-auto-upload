# 14: 在真实桌面客户端验收登录与并行草稿

Status: ready-for-human
Blocked by: 08, 10, 11

## What to build

取得可用的比特浏览器账号、启用 Token 鉴权的本机客户端和已登录的测试窗口后，逐项记录真机结果。目前各项均待验证。07–13 以离线契约验收，本单独立跟踪真机证据。

## Acceptance criteria

- [ ] 对大陆版小红书、Rednote、TikTok、Instagram、Facebook 个人、Facebook Page 和 YouTube，分别用桌面复制的窗口 ID 运行 `check`。逐项记录已复用登录态、stdout 仅有 `valid` 和退出 `0`。
- [ ] 在同一已登录两个平台的窗口并行运行 TikTok `upload-video --no-publish` 和 Instagram `upload-note --no-publish`。从两个独立编辑页分别读回本次草稿标记。TikTok 有发布前检查通过摘要，Instagram 报告 `prepared`，二者均退出 `0`、最终提交零次。
- [ ] 其中一条发布命令占用平台时再运行同平台 `check`。后来者在打开平台页面前提示占用并退出 `1`，原任务仍可编辑。
- [ ] 分别在窗口关闭和桌面预开两种初态下运行并行用例。冷启动合计一次打开，核对响应地址和随后从调试端口查到的地址可识别同一次运行。桌面预开合计零次打开。首条退出后其页面已清理、关窗请求为零，同行能追加并读回文字，预开场景还可读回桌面原标签标记。
- [ ] 末条退出时记录对同一 ID 的一次关闭请求，分别记录关闭回包、旧进程退出和原端口消失的时刻。再次冷启动时核实已经过至少 5 秒且旧进程已退出。
- [ ] 记录客户端及 Chromium 内核版本、命令与退出顺序、脱敏 API 计数、页面标记及最终窗口状态。实际遇到限流时记下 HTTP 状态和脱敏业务响应，每项凭对应证据标记真机通过，未观察的情况保留待验证。
