# 05 — 波次、回滚与文档同步

Status: resolved
Type: grilling
Blocked by: 01, 02

## Question

15 个平台不可能同时落地，而且只有 TikTok / Instagram / 小红书能做真机验收。要定的是「按什么顺序做、怎么退、文档改哪些」。

要定的事：

1. **波次**：第一波放哪几个？候选依据——(a) 有真机账号（TikTok、Instagram）；(b) 调用点最少（facebook 仅 1 fill + 2 click）；(c) 业务量最大（抖音、视频号、快手）。三者冲突时以哪个为准？
2. **回滚单位**：目前只有全局 `HUMANIZE=0`。是否需要按平台开关（例如 `HUMANIZE_EXCLUDE=tiktok,weibo`）？多一个开关就多一份契约，值得吗？
3. **验收门槛**：离线测试要断言到什么程度才算一个平台「完成」——只断言事件序列（走没走 `keyboard.press`、有没有 `mouse.move→down→up`、有没有 `force`），还是要连同「字段值最终等于预期」一起断言？
4. **真机验收记录**：TikTok / Instagram / 小红书 三家的验收要记录什么（发帖类型、字段、耗时、是否触发风控、帖子是否已删），落在哪个文件？未做的平台怎么标注？
5. **文档同步**：哪些必须改——`docs/CLI.md`（`HUMANIZE` 语义）、`GLOSSARY.md`（补「Humanize 交互层」词条）、`CHANGELOG.md`、各平台 `SKILL.md`？规格里要逐条列出，还是交给实施期判断？
6. **失败回退**：某个平台改严格后连续失败，是回退该平台到原生、还是保留并标注已知问题？

产出：波次表（平台 / 依据 / 验收方式）+ 回滚契约 + 完成定义 + 文档清单。

## Answer

六问全部关闭。以下每段可直接搬进 `spec.md`。

### A. 波次表与排序规则

| 波次 | 平台（交互点） | 依据 | 验收方式 |
| --- | --- | --- | --- |
| **W1 真机探针** | Instagram（16）、TikTok（45）、小红书（参照实现／回归对象，非移植目标） | 仅有的三个真机平台；覆盖 contenteditable 配文、iframe + `insert_text` 长文本、纯 `input` 短文本三种形态 | **真机（本地模式）+ 离线三条** |
| **W2 国外** | YouTube（8）、Facebook（10）、Facebook Page（22） | 国外平台收口；YouTube `_fill_editable` 的 `#` 浮层冲突在此消化 | 离线三条；标「未验证（无真机环境）」 |
| **W3 国内冲突** | 抖音（53）、微博（23） | 各一块硬骨头：抖音删 `_native_click`（8 处）、微博 `el.click()` 覆盖层 + 双 page（2 个 `Humanizer`） | 离线三条；标未验证 |
| **W4 国内主体** | 知乎（37）、大鱼（36）、视频号（34）、快手（28） | 无已知硬冲突，规模中等偏大，靠 W1–W3 已稳定的契约批量推 | 离线三条；标未验证 |
| **W5 国内长尾** | 支付宝（16）、百家号（15）、虎扑（15）、雪球（13） | 规模小、风险低，收尾 | 离线三条；标未验证 |

合计 61 + 40 + 76 + 135 + 59 = **371**，与 01 的对账一致。

**排序规则（写进规格）**：

1. **真机可验收的平台必须最先做** —— 真机是最稀缺资源，放后面等于让共享层缺陷先扩散到 12 个无可验证平台。
2. **分组优先于排序规则**：本轮由用户定的两刀硬分组（W1 = 三个真机平台；W2 = 其余国外平台）覆盖通用排序。
3. 分组内按 **冲突密度 > 调用点数量** 排。

**小红书的位置（写清楚，避免实施期误读）**：它不是移植对象，是**参照实现 + 回归对象**。若 08 决定改 `ensure_in_viewport` / `check`（同一个函数被小红书共用），W1 必须重跑小红书真机验收，确认共享层修复没把它弄坏；其验收结果同时是「共享层变更对已验证平台无回归」的唯一证据。

### B. 回滚契约

- **唯一的运行时开关是全局 `HUMANIZE=0`**，语义沿用 XHS：一次 `insert_text` / 一次普通 `click` / 零停顿。**不新增 `HUMANIZE_EXCLUDE`**。
- **回滚单位 = 平台提交**。每个平台一个独立改动集；线上出问题 → revert 该平台提交 + 重启。运行时不提供按平台退化路径（那会塞平台知识进零平台知识的 `Humanizer`，或让 15 个构造点各传平台名而漂移）。
- **不做运行时自动降级**（人类化失败 → 自动改走原生）。失败即失败，语义照 XHS：`Humanizer.click` 不传 `what`，`ElementMissing` = 选择器问题、`ElementUnusable` = 页面问题。
- **`force=True` 不得充当回滚网**（承接 03）：坐标点击失败不许改回 `force` 兜底。
- 测试矩阵因此只有 `HUMANIZE=1` / `=0` 两种，不随平台数指数膨胀。

### C. 「一个平台完成」的定义（离线三条，缺一不可）

1. **事件序列**：逐字符 `press` / 非 ASCII `insert_text`；每次输入末尾恰一次 `after_type`；点击是 `move → pointer_settle → hit-test(stillOn) → down → click_hold → up`；`stillOn` 失败不进 `mouse.down`；全程零 `force=True` 派发、零 `evaluate(el => el.click())`。
2. **字段值读回**：fake locator 持有键入缓冲，断言每个字段最终值等于预期。专抓「事件序列全对、值却错」—— 大鱼 `#author` 预填被抹、百家号标题「自动填了文件名」、任何清空不干净导致的追加。
3. **平台级静态门**：该平台包内 `fill(` 归零或列出书面例外、`el.click()` 归零、`force=True` 归零或只剩带 `# humanize-impossible: <失败模式>；<依据等级>；已排除替代` 同行的行、可见目标的裸 `.click(` 归零。

文件命名：每平台一个 `tests/test_<platform>_humanize.py`；共享契约继续留在 `tests/test_humanize.py`（已有 6 条契约 + XHS 包静态门，扩成 15 平台参数化）。

不采用「离线也要求 HTML 快照 fixture」：15 份易腐快照成本高于收益，真机验收已覆盖三家。

### D. 真机验收记录

落 **`.scratch/humanize-rollout/acceptance.md`**（沿用 `adspower-browser-mode/acceptance.md`、`tiktok-browser-parity/acceptance-local.md` 的惯例）。三平台各一节，每节一张执行表：

| 列 | 用途 |
| --- | --- |
| 日期 / 账号 | 可复现 |
| 发布类型（视频 / 图文 / 文章） | 三家交互路径不同 |
| 触碰字段（引 01 行号） | 失败时定位 |
| `HUMANIZE=1` 墙钟 / `HUMANIZE=0` 墙钟 / 差值 | 04 定的「只在这三家记双基线」落点 |
| 预算消耗（占 15 分钟多少） | 验证 clamp 没吃爆 |
| 是否出现验证码 / 滑块 / 风控提示 | 人类化唯一的外部效果观测点 |
| 帖子 URL + 是否已删 | 证明真发出去且清理干净 |
| 结论 pass/fail + 失败字段 | 决定是否 revert 该平台 |

- **浏览器模式列不设**：本轮**只验本地模式**（Patchright 自带 Chromium + cookie 登录），表头固定注明。托管模式行为一律「未验证」。
- 文件末尾固定一张 **「未验证平台」表**：12 个平台 × 「未验证（无真机环境）」× 离线测试文件名；与规格第 9 项「未验证清单」一一对应。
- 撞击新卡死模式（`stillOn` 反复失败、动画按钮、hover 漂移）时，必须记目标 locator 与重试次数 —— 地图 `Not yet specified` 那条只能靠这个证据关闭。

### F. 失败回退

- 不在运行时回退。某个平台改严格后连续失败 → **revert 该平台提交**，`HUMANIZE` 全局仍为默认开启，故障与「已退回原生」的事实写进 `acceptance.md` 的「未验证／已知问题」表。
- 不保留「失败平台继续跑人类化 + 标注已知问题」的双形态：两套代码路径会让离线测试与真机记录失去可比性。

### G. 托管模式（本轮范围修正）

- 用户当前无托管账号，**托管模式不进本轮验收、不进波次门槛**。
- 影响：08 的缺陷 2（`connect_over_cdp` 强制 `noDefaultViewport` → `page.viewport_size is None` → `ensure_in_viewport` 静默退 1280×720）不再阻断本轮；最终「修／绕过／接受」仍由 08 决定，本工单只提供「本轮无托管账号」这条事实。
