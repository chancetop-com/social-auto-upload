### 汇总时必须补齐的 5 处（03/07 的边界留下的空档，规格按既定判据收口）

1. **9 处 `el.click()` 的逐条去向**：03 §9 把「`el.click()` 归零」交给 07，但 07 只裁了微博三处。规格补齐：微博 `:861/:912/:941` 照 07；抖音 `:849`、视频号 `:1076`、TikTok `:2390`、IG `_rows.py:110/:130` 全删（失败即硬错，不用 JS 兜底）；抖音 `:686` 走 02 §6.3 的「hover 显形 → 坐标点击」，仍 hidden 则硬失败。依据仍是 03 的判据顺序，不新增豁免。
2. **TikTok 话题 `:2338`**：01 标「待定（必须整段插入）」，与 07 §2 的 YouTube 结论冲突。规格按 07 的统一口径改为**逐字 + 候选全等**，失败保留纯文本（XHS/YouTube 同构），进 §9 未验证。
3. **抖音 `:686`（BGM 使用按钮）**：02 §6.3 只给建议，未定「仍 hidden 怎么办」。规格定为硬失败，不回退 `el.click`，与 charter 一致。
4. **视频号 `:684`、IG `:241`**：`ElementHandle` 目标不在 Humanizer 可接受面内，规格要求先换 `Locator` 再 `H`（`:671/:676/:687` 的 `page.click(selector)` 同理）。
5. **门 B / 门 D 的形态**：05 只说「可见目标裸 `.click(` 归零」「`fill(` 归零或列例外」，未给可执行形式。规格定为行内标记门（`# native-click: <类>；<原因>`、`# native-fill: <原因>`），与门 C 同构；§3 的 54 个 `N/*` 行就是登记册。这是 05 §C.3 的执行化，不是新增约束。

### 与 04–08 的一致性自查

- 04：阈值 1000 唯一、16 个 bulk 字段逐条登记（§2.7）、`sleep=budget_clamped_pause` 强制、0 删 1 增 wait、只三平台记双基线。
- 05：五波 + 新增 W0（08 的修复必须先落地，否则 W1 用的是错的共享层）；回滚只有 `HUMANIZE=0` + revert 平台提交；文档四处随 W1。
- 07：四处冲突零豁免（微博比例落点、YouTube 逐字+候选、搜索型逐字+全等、抖音删 `_native_click`）；热点在波内置顶。
- 08：hover 漂移不改 `click`（调用点按需 `hover`）、视口判定去尺寸化（谓词）、容器裁剪两级谓词；overlay 仍走 `check` 硬失败。
