## What to build

在模拟 MLX Launcher 中重现与 AdsPower 相同的故障，让命令根据当前 Profile 与连接状态恢复，分别保留每个发布任务的结果。

## Acceptance criteria

- [x] 分别终止一条或全部 CLI，验证退出进程的平台资格释放、仍运行的同行可继续。对一直保持活动和手动重开的 Profile，下一条命令使用当前连接新开页，最后离开时只发一次 Stop。
- [x] 使 Start 响应丢失，再依次模拟活动且可连接、已确认空闲、仍在启动、状态未知或连接不可用。检查正式 CLI 的诊断与 Launcher 调用次数；只有确认空闲时可重启，结果未知时无补偿 Stop。
- [x] 在旧会话停止过程中申请已空闲的平台，验证有界等待和超时退出。Stop 失败只告警，保留主操作结果。在 Stop 已结束时按当前活动或空闲状态处理。
- [x] 检查同行与已落盘的结果、适用的退出码及提交次数。新命令不重新提交旧草稿，也不为被强杀的命令补写结果。

## Comments

从正式 CLI 经模拟 Launcher 验证了单个进程与全部进程被杀、原浏览器仍在、浏览器被关闭再重开、Start 回包丢失、Stop 延迟及限时退出。恢复前后回读登录状态、原草稿和结果文件，实际提交次数未增加。Launcher 确认收到 Stop 与旧实例实际退出之间存在时间差；协调层核对当前实例，对仍在执行或结果不明的操作有界等待。确认空闲与已打开所需证据见 [CLI 使用说明](../../../docs/CLI.md)。浏览器、客户端与会话组合通过 99 项测试和 11 个子用例。最终收紧 Stop 错误识别后，客户端复验通过 29 项和 6 个子用例。验收提交为 `6fff5e3`。
