## What to build

AdsPower 上的同行在另一进程崩溃后继续工作。下一条 CLI 通过指定 Profile 的当前状态恢复使用，保留已有结果及旧草稿。

## Acceptance criteria

- [x] 在 Mac 用两个独立 CLI 和可控 provider 强杀其中一条。被杀进程的平台资格释放，另一进程继续编辑并持有自己的平台资格。新命令可在已释放的平台另开页，旧草稿仍留在原页。
- [x] 强杀全部 CLI 后分别保留原浏览器、从桌面关闭后重开。下一条命令取得指定 Profile 的当前连接，另开页面，最后离开时一次 Stop。无需辨认最初由谁启动。
- [x] 注入 Start 响应丢失或无可用连接信息。后继命令重新查询，确认已打开且可连接时加入，确认启动已结束且空闲时才重新 Start。仍在启动、状态未知或无法取得当前连接时报告原因并退出。核对无重复 Start、无补偿 Stop。
- [x] 让新命令在旧会话 Stop 期间到达。申请的平台已空闲时有界等待；确认停止后重新申请，超时或结果仍未知时带原因退出。Stop 失败只告警，保留离开者主操作的退出码与结果。
- [x] 用可控页面记录实际提交次数，并检查已落盘的结果。被强杀的命令可以缺少结果或退出码，恢复流程不代写结果、不续点旧草稿；若可能已提交，由调用方核对作品后再决定是否重跑。

## Comments

以独立 CLI 和本机 Chromium 运行 19 个故障恢复场景，覆盖单进程与全部进程被杀、桌面重开、Start 已发出但回包丢失、Stop 仍在进行及拒绝操作。终止后重新加入者操作自己的新页，未生成的结果文件保持缺失，已有的 Instagram 结果逐字节保留，观察到的两次提交在恢复后仍为两次。Python 3.10.16 的 CLI 在 Stop 中收到中断时仍持有生命周期锁；3.12.9 的竞争进程按界限退出。反向版本组合也验证了状态查询超时。19 个场景连同 AdsPower 客户端与共享检查合计通过 75 项和 4 个子用例，最终提交为 `1c39a2f`。
