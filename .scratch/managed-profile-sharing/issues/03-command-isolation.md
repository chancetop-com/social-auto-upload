# 每个托管动作怎样只操作自己的页面和内容

Label: wayfinder:grilling
Type: grilling
Status: resolved
Assignee: LukeChen

## Question

为每个已有托管 check 和发布入口确定隔离边界与逐项验证方法。Instagram 编辑中遇到 TikTok 回退到第一个标签页、微博打开子窗口、不同平台的两个文章编辑器先后写入共享剪贴板时，怎样保证一条命令只导航及清理自己创建的页面，且实际提交给平台的内容属于本命令？包括探测登录态的临时页面。讨论并行情形时，以[谁负责加入、离开和停止共享托管会话](02-process-lifecycle.md)确定的加入条件为准。

## Comments

2026-11-18，用户确认以下发布前行为。

- TikTok 丢失自己的标签页时，本次命令报错退出。Instagram 继续在原标签页编辑。
- 微博从本命令的首页等待视频编辑器弹窗。等到现有超时仍未收到时，本次命令报错退出，只清理能确认归属的页面。
- 文章粘贴后做弱校验。允许编辑器改写 HTML、空白、换行、排版和图片地址，回读结果可以与原稿有差异。仍须从编辑器中读到可核对的内容，明显错贴或正文意外为空时在发布前报错。

## Answer

每条命令在共享 Profile 的现有浏览器上下文里新开自己的页面。主编辑器、登录探针、预览页和结果核对页都按同一规则管理。由本命令页面直接打开、且能追溯到该页面的弹窗也归这条命令。导航、输入、监听发布结果和退出清理都限定在这些页面上。标签顺序、当前焦点、URL 相同或「调用后刚出现」都无法单独证明页面归属。

- **页面丢失与超时。** TikTok 发布必须新开页面，移除托管发布路径里按 URL 或首标签选页的回退。提交前丢失自己的页面就报错退出。微博从发起点击的首页等待编辑器弹窗，按现有超时退出时只清理已确认归属的页面。知乎视频在发布后打开详情，也从自己的发布页识别弹窗。发布后的页面故障沿用该动作已有的发布结果与退出码语义，禁止因此再次点击发布。[TikTok 选页](../../../uploader/tk_uploader/main_chrome.py) · [微博编辑器](../../../uploader/weibo_uploader/main.py) · [知乎视频详情](../../../uploader/zhihu_uploader/video.py)
- **正文粘贴与回读。** 大鱼号、知乎和雪球文章当前使用原生剪贴板，知乎还逐张粘贴 PNG。共用同一剪贴板的 CLI 进程须协调每次写入与粘贴，从写入本次数据到本命令的编辑器取走数据，另一条命令才能开始下一次写入。等待 `--not-before` 期间无需占用剪贴板。正文回读采用弱校验，例如忽略空白后检查本次原稿中有辨识度的文本片段。编辑器合段、改排版或改写图片地址都可以通过。读不到可核对的内容、正文意外为空或明显错贴，均在点击发布前报错。[大鱼号文章](../../../uploader/dayu_uploader/article.py) · [知乎文章](../../../uploader/zhihu_uploader/article.py) · [雪球文章](../../../uploader/xueqiu_uploader/article.py)
- **Facebook 发布目标。** 在并发验收中让个人账号和 Facebook Page 分别进入自己的编辑器，一方等待 `--not-before`，另一方选择目标主页。等待前后分别观察个人发帖主体、Page 名称及可见的主页标识，核对两边仍指向预期目标。这项决定只要求在验收时观察。现有证据尚未表明选 Page 会切换另一个标签页的个人身份。[Page 目标选择](../../../uploader/meta_uploader/facebook_page_uploader/main.py)

### 逐入口验证

按 CLI 实际注册的托管动作逐项覆盖。下表每个「平台 × 动作」各运行一例，共 17 项 `check`、16 项视频、8 项图文、3 项文章。Rednote 与大陆版小红书分别计入。[CLI 注册表](../../../sau_cli.py) · [Rednote 注册](../../../sau_commands/rednote.py)

| 平台 | 每个平台验证的托管动作 |
| --- | --- |
| 抖音、快手、小红书、Rednote、Facebook 个人、Facebook Page、Instagram、TikTok | `check`、`upload-video`、`upload-note` |
| 视频号、支付宝生活号、微博、虎扑、YouTube、百家号 | `check`、`upload-video` |
| 大鱼号、知乎 | `check`、`upload-video`、`upload-article` |
| 雪球 | `check`、`upload-article` |

每例在同一上下文预置另一条已获准命令的页面，放入可识别的草稿。记录被测命令打开、操作和关闭的页面，以及本命令收到的检查或发布结果。成功及失败清理后，同行页面仍能继续编辑，草稿与导航位置均应保留。登录探针单独核对其临时页已关闭。发布入口在测试中区分提交前失败、已提交和结果未知。真实账号在最终提交前停止。

交错场景优先覆盖 Instagram 草稿仍在编辑时 TikTok 启动或丢页、微博等待弹窗时同行新开标签，以及两个文章平台交替粘贴不同正文或图片。文章测试用不同标记核对两份实际输入，包括「图片数量相同但图片不同」和「正确正文被编辑器改写」两例。前者验证粘贴归属，后者验证弱校验能接受正常改写。桌面实测与自动化证据的分工由[哪些证据足以验收托管 Profile 默认共享](05-acceptance.md)确定。
