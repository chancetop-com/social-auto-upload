## Question

应如何标识同机同一个托管 Profile，协调同时启动、加入、最后退出与新任务到达？比较本机进程锁与单一会话管理进程，明确不同平台、Python 版本、启动参数冲突、旧版 CLI 或外部进程并存时可以承诺的行为。凭据与浏览器连接地址如何限制在本机相应用户范围内？

## Comments

2026-11-18，用户已确认两项行为，协调方式待比较后决定。

- 最后一个使用者已经开始停止 Profile 时，新命令有界等待。确认旧会话已停止后才能重新申请启动。等待超时或停止结果不明时，新命令报告原因并退出。
- 新命令明确要求的启动参数与当前会话冲突时，在打开页面前拒绝新命令。已经加入的任务继续按原设置运行。

用户选定本机进程锁方案。每条独立启动的 CLI 命令在使用 Profile 期间持锁。启动者可以先退出，最后离开的使用者负责归还 Profile。

同一 Profile 的同一平台同时最多执行一条托管命令，`check` 和所有发布入口都算。后来者在打开页面前立即报告该平台占用并退出。小红书即使在等待 `--not-before`，另一条小红书命令也要立即退出，TikTok 仍可加入。只有在平台已空闲、旧会话正停止时，新命令才按前述规则有界等待。

现行 CLI 已将托管 Profile 占用归入退出码 `1`。同平台占用可以沿用该契约，并在诊断中指明被占用的平台。[CLI 退出码](../../../docs/CLI.md#退出码)

## Answer

采用本机进程锁。每条命令独立持有使用资格，启动 Profile 的命令可以先退出。独立的会话管理进程可以在所有客户端崩溃后尝试清理，但还需要处理管理进程自身的启动、退出和恢复。本轮接受最后一条 CLI 被强杀后 Profile 可能保持打开。遗留会话的处理由[进程中断后怎样识别和恢复遗留会话](04-abandoned-session.md)决定。

- **哪些命令协调。** 同机、同一操作系统用户下，以 provider 和 Profile ID 标识要协调的 Profile。从不同工作目录、安装位置或 Python 虚拟环境启动的兼容 CLI 使用同一组锁。MLX 的 folder 和 AdsPower 的服务地址用于核对请求指向的资源。仅改变 folder、地址拼法、凭据或账号别名，不能为同一 Profile 取得第二组锁。无法确认指向同一资源时拒绝加入。
- **谁可以加入。** 一个平台从取得资格起到命令离开为止只能有一个使用者，包括启动、登录检查、发布准备和 `--not-before` 等待。同平台的后来者在打开页面前立即报告该平台占用，以 `1` 退出。Facebook 个人账号（`facebook`）和 Facebook Page（`facebook-page`）是两个平台，可以在同一 Profile 上并行。两条 `facebook-page` 命令即使指定不同主页也互斥。大陆版小红书与 Rednote 分属两个平台。不同 Profile 各自独立。
- **同时启动和正常离开。** 同一 Profile 的首次启动、加入登记和最后归还按顺序协调。不同平台同时申请时，只允许一个启动者向 provider 发出 Start。Profile 已经打开时，命令核对指定 Profile 的当前连接及启动参数兼容性后加入。新命令明确要求的启动设置与运行中的会话冲突时，只拒绝新命令。各命令执行期间独立持有资格、操作自己的页面并产生自己的结果。
- **谁可以停止。** 在同一 Profile 的进程锁协调下判断还有多少条已加入的托管命令。仍有其他命令使用时，离开者只清理自己的页面，释放资格。最后一条命令负责关闭整个 Profile，即使它最初由用户从桌面打开、桌面标签页仍在使用。加入失败的命令没有退出清理责任。新命令申请的平台已空闲、旧会话正在停止时，有界等待确认停止后再申请。超时或结果不明则报告原因并退出。[进程中断后怎样识别和恢复遗留会话](04-abandoned-session.md)
- **版本和权限。** 在项目支持的桌面环境和 Python 3.10–3.12 中，版本兼容以能够遵守同一套锁和会话记录规则为准。无法取得可靠的锁或无法安全读取记录时，命令在接管浏览器前退出。旧版 CLI、其他操作系统用户和独立工具不受本用户的锁约束，混用时由调用方串行。各命令用自己的环境凭据访问 provider。共享记录与连接地址限当前用户读取，token、API key 和 CDP 地址不得出现在日志中，token 和 API key 不写入共享记录。

macOS 示例只验证了模拟 provider 的进程锁与正常退出顺序。不同操作系统上的锁与权限、跨虚拟环境协调及两家真实 provider 的最后退出行为仍需验收。[双进程示例](../../../examples/shared_profile_demo.py) · [哪些证据足以验收托管 Profile 默认共享](05-acceptance.md)
