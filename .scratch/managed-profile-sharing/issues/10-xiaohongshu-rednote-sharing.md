# 10: 大陆版小红书与 Rednote 独立检查和发布

Status: resolved

Blocked by: 08

批次：第一批 · [托管 Profile 默认共享规格](../spec.md)

## What to build

让大陆版小红书与 Rednote 按两个平台共用 Profile。一个平台等待发布时，另一个平台仍可工作，同平台的第二条命令立即收到占用结果。

| 平台 | 本单负责的托管入口 |
| --- | --- |
| 大陆版小红书、Rednote | `check`、`upload-video`、`upload-note` |

## Acceptance criteria

- [x] 从正式 CLI 离线逐项覆盖六个入口。为同行预置带标记的草稿，核对两边各自的探针、编辑器、检查或发布结果。每种动作的成功及失败清理后，同行仍停留在原处并可继续编辑。
- [x] 用可控时间使大陆版小红书实际进入 `--not-before` 等待。分别让 Rednote 发布命令和 TikTok 检查命令加入；两种情况下第二条大陆版小红书命令都在开页前报告平台占用，以 `1` 退出。测试使用会进入等待的发布路径，`--no-publish` 会跳过等待。
- [x] 同一平台分别验证检查与检查、检查先于发布、发布先于检查、发布与发布；同时申请时只有一条命令获准。资格从命令开始持续到清理结束。不同 Profile 可以独立运行同一平台。
- [x] 各命令按自己的闸门时间与平台结果结束。一方失败或已发出发布点击时，核对双方提交次数、退出码和适用的提交信号，同行继续按原定时间执行。

## Comments

15 个离线双进程场景覆盖小红书与 Rednote 的六个正式入口、同平台四种抢占顺序、不同 Profile，以及等待中的 TikTok 同行。通过生产的发布时间闸门分别推进两个时钟，实际回读草稿和提交记录。同行先离开、失败或者清理仍在进行时，另一边的资格和草稿受到保护。修复了点击发布后跳转登录页被误报为成功的问题，两端均只点击一次，返回 10 与 `publish_attempted=true`。验收提交为 `74a7b0e`。既有平台回归通过 385 项和 105 个子用例，68 项直接相关的回归在 Python 3.10、3.11 和 3.12 均通过。
