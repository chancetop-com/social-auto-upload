# 34 — 人类化交互：逐字符打字与坐标点击

**What to build:** 小红书链路里的每一次打字和点击都走一套共享的行为层：ASCII 逐字符真按键、中文逐字符插入、超长正文一次性批量插入；点击走贝塞尔移动 + 落点复核 + 按下保持。同一个 seed 完全可复现，`HUMANIZE=0` 时退化为零时延快路径。

**Blocked by:** 32（点击前的 `interactive` 落点复核、DOM 夹具）.

**Status:** ready-for-agent

- [ ] 11 个动作的参数表（均值/σ/上下界）原样落成唯一定义，平台不得复制；平台差异只允许派生副本
- [ ] 打字：长度 ≤1000 逐字符——ASCII 走真实按键事件，中文/emoji 走插入文本，每字符后采样按键间隔；长度 >1000 一次性插入，零按键、零采样，并打一条 info 说明批量插入与字数
- [ ] 每次输入结束都走一次"输入后停顿"
- [ ] **禁止**剪贴板粘贴、**禁止** `fill()`；清理键保留并走采样；全选快捷键在 macOS 下有效
- [ ] 点击顺序固定：包围盒 → 内缩随机落点 → 贝塞尔移动（步数随距离收紧）→ 指针稳定停顿 → 落点复核（元素仍是目标、位置 ±1px、`interactive` 档）→ 按下 → 保持 → 抬起
- [ ] 内部零重试（重试只发生在 ARM）；包围盒不可得或复核不符 → 抛"确定未派发"；按下之后任何异常 → 标记"可能已派发"
- [ ] 小红书接线：导航后一次、每次点击、每次文本输入完、FIRE 前一次、真实滚动处；`Reading`/`AfterInteract`/`BeforeClick`/`AfterClick` 不接
- [ ] 小红书目录内 `fill(` / `el.click()` / `force=True` 静态计数为 0（YouTube 的豁免不在本票）
- [ ] 测试：字符分派、1000/1001 边界（1001 恰一次插入、零按键）、点击序列、复核失败时无"按下"、同 seed 可复现、`HUMANIZE=0` 零停顿
- [ ] 记录时间上界：20 字标题 ≈2.7s、1000 字正文 ≈2.3min、10 标签 ≈10.9s，总计 ≈2.6min，仍在 15 分钟预算内
- [ ] 真机 dry-run：`--no-publish` 走通；`HUMANIZE=0` 对照同输入走通
