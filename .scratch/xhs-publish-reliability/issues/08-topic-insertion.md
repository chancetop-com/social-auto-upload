# 08 — 话题插入校验与编辑器状态

Status: resolved
Type: grilling
Blocked by: 02, 05
Assignee: wayfinder-session (opencode)

## Question

决定话题插入是否校验、怎么校验、失败怎么办。需要确认：

1. **回读校验**：是否采用 `a[data-topic]` 回读——数量必须 +1、`data-topic.name` 必须与请求相等（大小写不敏感）？不满足时抛错还是降级为纯文本？
2. **候选选择**：现在点 `#creator-editor-topic-container .item` 的**第一个**且不校验名字。改为按 `.name` 文本精确匹配？找不到时怎么办？
3. **无候选时的正文形态**：上游保留纯文本 + 补空格；我们回退 `Backspace` 删除。选哪个？对最终正文的影响要给出样例。
4. **输入前复位**：上游先按 20×ArrowDown + 2×Enter 复位光标/联想状态。是否需要等价动作？它的作用是什么（若无法确证，标注“仅推断”）。
5. **上限单一口径**：CLI 现 >10 直接报错，运行时又静默截断到 10。选一个。

产出：话题插入步骤表（含每步的失败分支）+ 正文最终形态样例 + 上限口径。

## Evidence from 02（真机取证）

- 插入 1 个话题后，`a[data-topic]` 出现 **2 个同值节点**，`data-topic` 均为 `{"id","link","name"}`，`name` 不含 `#`；可见文本 `#旅行pov[话题]#` 与 `#旅行pov` 各一。
- 上游「数量严格 +1」判据在现网会误判；需改为「按 name 集合变化」或「正文出现该话题锚点」。
- 候选容器 `#creator-editor-topic-container .item .name` 可用（单次 50 项）。

补充事实（`research/raw/controls-topic-suggest.json`，请求词 `旅行`）：候选**按热度排序、不按接近度**——第 1 项是 `#旅行pov`（10亿浏览），精确的 `#旅行` 在**第 4 位**（372.9亿浏览）。因此「首项不等即判无候选」的短路会误降级。

## Answer

**决议**：话题是**增强项**——缺失一律降级、绝不因缺失中止发布；但**插错必须中止**。候选按 name **精确匹配**、**顺序全扫**；重试沿用上游「找→点」循环（它把"候选消失"隐含当成功）；成功判据改为编辑区**集合比对**（编辑区内恰好 1 个新增、name 全等）；无候选保留纯文本 `#tag` + 一个空格；**不抄**上游的 `ArrowDown×20 + Enter×2`；标签上限**截断**为唯一口径。

### 1. 总体契约（Q1）

| 情形 | 动作 | 出口 |
|---|---|---|
| 候选未出现，或 3 次点击后 **0 个新增** | **降级**：保留纯文本 `#tag` + 一个空格，继续下一个标签 | 无失败 |
| 新增 ≥1，但有新增节点的 name **≠ 请求 tag**（含 `data-topic` 解析失败） | **中止**（点击发布前） | exit **1** |
| 新增 **> 1**（编辑区内） | **中止**（同一话题被插入多次） | exit **1** |
| 恰好 1 个新增且 name 全等 | 成功，继续 | — |

> **23 真机修订（2026-11-11）**：编辑区内每次插入恰好 +1；02 观察到的「2 个同值锚点」是 1 个编辑器节点 + 1 个预览镜像。原「1–2 个新增」会把双插（2 个）误当成功，故收紧为「恰好 1 个」。详见 `research/23-topic-multi-insert.md`。

- 中止归入 05「找到但不可用」档（第 7 行），`reason=topic-mismatch` / `topic-multi-insert`；错误携带 `tag`、`observed_names`、`new_nodes`、`attempts`。**不新增退出码**（03 pre-click = 1）；具体异常名由 17 定。
- 「缺失降级」的理由（①）：为一个可选增强项重跑整条发布 = 多一次发布尝试，风险大于收益。
- 「插错中止」的理由：这是唯一能确知「正文与请求不符」的时刻；且说明候选匹配命中了错误节点，不该继续。

### 2. 候选匹配（Q2）

1. 顺序扫描 `#creator-editor-topic-container .item` **全部**渲染项（真机单次 50 项），对每项读 `.name` 的 `text_content()`（不依赖可见性；可见性由 06 的 `INTERACTIVE` 单独判）。
2. 归一化（两侧同规则）：去前导 `#` → `strip` → 内部连续空白折叠为一个 → `casefold`。
3. **只点 name 全等**的项；多个全等 → 取**排序最前**的那个，打 `info`（`topic-ambiguous:N`）。**没有全等即判无候选**，不做前缀/包含匹配。
4. `#creator-editor-topic-container` 需 `ATTACHED`；被点的 `.item` 需 `INTERACTIVE`（06）。
5. 收益：消灭「点第一个 = 插入热度最高项、与请求无关」这条错内容通道。

### 3. 候选出现与重试（Q3 = 上游口径）

1. 轮询 **200ms**，deadline `min(5s, budget.clamp_seconds(5))`；每轮**重新扫**全等项（列表会重绘，不复用 locator）。**就绪条件是 `.item` 数 > 0**，不是容器 `visible`：23 实测容器在键入后立即以 0 项空壳出现（1–111ms），随后消失/重绘，约 430–570ms 才出现 50 项。
2. 找到 → 过 `INTERACTIVE` → 点击。**最多 3 次点击**。
3. 循环退出条件：连续找不到候选 / 用满 3 次 / deadline 到。
4. 循环后统一做一次回读（§4）。重试条件**只看"还能不能找到候选"**（上游语义）；**不在循环内回读**。

> 已知代价（安全方向）：若点击成功后下拉**不关闭**，第 2 次点击会再插一次 → 回读得 2 个新增 → 按 §1 判「多插」**中止**。是安全的失败方向，不会静默发错内容。**23 实测下拉在 0–2ms 内从 DOM 移除**，故这是理论风险而非现实路径；保护仍保留。

### 4. 回读判据（Q4）

1. **作用域**：正文编辑器根内（`div.tiptap[role=textbox]`，05 第 3 行）；不查整页，避免把别处锚点算进来。**23 实证**：整页查询会把右侧图文预览的镜像锚点也算进来（每次插入 1 编辑 + 1 预览），编辑区内才是真正要判定的节点。
2. **基线 `S0`：每个标签条目（`tags` 列表的一次循环）在第一次点击前取一次；同一条目的重试**不刷新**。新增 = 点击后集合 − `S0`（多重集合差）。
   > 纠偏：Q4 对话中曾写「每次重试前刷新基线」，那是错的——双插时刷新会把前一次的 1 个节点吞进基线，第 2 次插入的 1 个新增会伪装成正常。**基线按标签固定。**
3. 轮询 **50ms**，窗口 `min(1s, budget.clamp_seconds(1))`（与上游同量级、与 05 第 7 行文案一致）。
4. 取 `data-topic` → JSON → `name`；解析失败算「name 未知」→ 插错。
5. 判定：编辑区内新增恰好 1 个且 name 全等 → 成功；0 个 → 缺失；>1 个 → 中止（§1，`topic-multi-insert`）。
6. 锚点只需 `ATTACHED` 档（读属性，不需可见）。

### 5. 无候选时的正文形态（Q5 = 上游口径）

保留纯文本 `#tag`，**补一个空格**，打 `warning` 继续。**绝不**用 `Backspace` × N 清理：连击是机器节奏（①），且一旦打字未全落地就会**多删正文**（不可逆）。

（`desc = "海边的日落"`，`tags = ["旅行","治愈"]`，`旅行` 无候选、`治愈` 正常插入）

| 口径 | 正文 |
|---|---|
| 现状 | `海边的日落⏎#治愈[话题]#` |
| **本票** | `海边的日落⏎#旅行 #治愈[话题]#` |

- **不做标签去重**：与上游一致，标签原样处理。（去重只影响正文整洁，不影响 §4 判定——基线按**标签条目**取，同一标签重复出现时新条目重新取基线，仍判 1 个新增。）

### 6. 输入前复位（Q6 = 不采用）

- **不做** `ArrowDown×20 + Enter×2 + sleep 1s`。理由：① 10 标签 = 220 次 key 事件 + 10s 盲睡，是最典型的机器节奏；② 无真机证据表明必要（02 的插入取证即在无复位前提下完成，标注「仅推断」）；③ `Enter×2` 在 tiptap 里通常生成两个空段落，可能污染正文。
- 复查条件：真机连续插第 2+ 个话题时下拉不出现 → **只补最小等价动作**（`Control+End` 一次 + 200ms），不整体照抄（见 23）。
- **23 真机结论（2026-11-11）**：连续插 `旅行 → 美食 → 穿搭` 三个话题，第 2/3 个直接键入即出现候选，**不需要任何复位动作**；复查条件未触发，维持「不采用」。
- 标签的键入节奏（`#` 与 tag 之间是否停 200ms、`delay=30` 是否保留）归 **10**，本票不定。

### 7. 上限单一口径（Q7）

- 判定只在一处：`validate_upload_args()`（发布前、开浏览器前）。`>10` → 打 `warning` 列出被丢弃项，`self.tags = tags[:10]`。
- 删除 `fill_tags` 里的运行时截断（流程中途不得再改内容）；CLI 两处 `>10` 由「报错退出」降为**同文案 warning**。
- 结果：CLI / 库调用方（`examples/`、`myUtils/postVideo.py`）/ 两种运行模式行为一致。
- 理由（①）：报错会新增失败路径——调度侧若对 exit 1 重试，纯装饰性的标签超限会变成反复起浏览器。

### 8. 与上游的偏离（按 charter 记录理由）

| 项 | 上游 | 本票 | 理由 |
|---|---|---|---|
| 回读数量 | 严格 `previous+1` | 编辑区内**恰好 +1** | 02 的「2 节点」= 1 编辑器 + 1 预览；整页作用域下上游判据必挂，限定编辑区后 +1 成立（23 已证） |
| 回读方式 | 记 count、取 `nodes[previous]` | `{name}` 多重集合差 | 与节点顺序/重渲染无关；可抓「两次各 1 个」 |
| 无候选 | 保留 `#tag` + 空格 | **采用** | 同上游 |
| 候选匹配 | name 全等（去 `#` + TrimSpace + EqualFold） | **采用**，并显式要求顺序全扫 | 真机热榜排序会漏（`#旅行` 在第 4 位） |
| 重试 | 5s/200ms/3 次，点前重找 | **采用** | 重试发生在派发前，①风险为零 |
| 输入前复位 | ArrowDown×20 + Enter×2 + 1s | **不采用** | ① 成本 + 无证据 + 可能加空段落 |
| 上限 | 截断 | 截断，但收敛到校验期一处 | CLI 报错会造成重试压力 |

### 9. 需真机验证（23 已全部取证，2026-11-11）

1. 连续插入第 2+ 个话题时，联想容器是否仍出现（决定 §6 是否补 `Control+End`）。→ **仍出现，无需动作**（23）。
2. `a[data-topic]` 是否**始终**位于 `div.tiptap[role=textbox]` 之内（§4-1 作用域假设）。→ **编辑器节点是；另有预览镜像在编辑器外**（23）。
3. 成功点击后下拉是否关闭（§3 的双插中止是否会被现实触发）。→ **0–2ms 内关闭并从 DOM 移除**（23）。
4. `.name` 是否始终带前导 `#`（02 样本带；归一化已兼容两种，仅影响日志可读性）。→ **采样 30/30 全带**（23）。
