# 27 — 定时设置后的单次回读（决策）

Status: resolved
Type: grilling
Blocked by: 11, 26
Assignee: wayfinder-session (opencode)

## Question

26 的真机取证把 11 的「定时设置结果不可观测」缺口拆成了两半：

- **定时开关**：状态可读（`.post-time-wrapper .d-switch-simulator` 的 `checked`/`unchecked` + `.date-picker-container` 出现/消失），点击三次均可逆，未观察到失败样本。
- **定时时间**：输入框是受控组件；过去日期/不可解析串在**失焦后静默回滚**到上一次合法值（默认 `now+1h`），无任何错误文案。当前流程写完不回读、也不主动失焦，因此会按回滚后的时间发布。

需要决定是否在 FIRE 前补一次「失焦 + 单次读回」，以及读什么、何时读、不一致怎么办：

1. **覆盖项**：只读开关（simulator class + 日期输入 attached）？还是连时间值一起读（`input.value ==` 写入串）？
2. **时机**：写完时间后立刻 `blur()` + 读（此时页面已完成校验）？还是放在 03 的 ARM 就绪后、FIRE 前读（更接近提交）？两处都读是否重复？
3. **不一致动作**：`exit 1`（确定未发布，`publish_attempted=False`）还是 warning 继续？与 11 的「原创 true 失败 → exit 1」是否同口径？
4. **失去定时语义的风险**：回滚值是 `now+1h`，若我们只是 warning 继续，会按错误时间发布；是否因此强制 exit 1？
5. **不许用 Tab/Enter 失焦**：26 观察到 Tab 会把焦点送到 `xhs-publish-btn`，随后 Enter 触发「暂存离开」并离开编辑器（两次复现）。失焦只能用 `blur()`（或点非提交区）。
6. **退出码**：点击前 → 1；不新增退出码，不产生 9。

产出：定时项 × 回读信号 × 时机 × 不一致动作 表；并给出 17 应如何改写 11 的「已知缺口」（从「不可观测」改为「可观测但本轮未实现」或「已实现」）。

## Answer

### 决议（2026-11-11）：补，分三处断言；不一致一律 `exit 1`

不采用 11 的「完全采纳上游（含缺口）」。该口径拍板于 26 取证之前；26 证明「日期被拒 → 失焦静默回滚 → 按错误时间发布」真实存在，且平台不拦（越限时 `submit-disabled` 仍 `false`），所以点击前检查是唯一闸门。**上游同样没有回读**（`xpzouying/xiaohongshu-mcp` `main` 2026-11-10：`setSchedulePublish` 1476 → `clickScheduleSwitch` 1493 只点不读 → `sleep 800ms` → `setDateTime` 1510 `SelectAllText` + `humanize.Type` → `sleep 500ms`，无 `blur`、无 `input.value` 读；唯一校验是 `service.go:228-229` 的 `now+1h ≤ t ≤ now+14d`，在浏览器启动前）。**「上游没有」不构成理由**，按 charter 记一次「禁止对齐下界」偏离。

### 检查点 × 信号 × 时机 × 不一致动作

| 检查点 | 定时项 | 回读信号（结构优先、零文本） | 时机 | 不一致动作 |
|---|---|---|---|---|
| **C1 设置后** | 开关 | `.post-time-wrapper .d-switch-simulator` class **含 `checked` 且不含 `unchecked`**；且 `.date-picker-container input` **attached** | 点击开关后；就绪等待沿用 06（目标自带信号 + 一次 DOM 静默，夹在预算内），**不再用固定 `sleep(1)`** | `exit 1` |
| **C2 写入后** | 开关 + 时间值 | 开关同 C1；`input.value` 以 `%Y-%m-%d %H:%M` **解析后按分钟** == 请求值 | `blur()` → **约 300ms 后单次读**（不是轮询） | `exit 1` |
| **C3 FIRE 前** | 开关 + 时间值 + 时效 | 开关同 C1；值同 C2；且**请求值仍 > `now()`**（墙上时间，与 11 同口径） | 03 的 ARM 就绪后、FIRE 前；即 `wait_until_allowed(--not-before)` **之后** | `exit 1` |

### 为什么是两处读、各管一段（不是重复）

- **C2 快失败 + 可归因**：回滚发生在 `blur()`，此时读到不一致就能直接报「日期被页面回滚」，不必等整条链路走完；错误信息含「请求值 / 实际值」。
- **C3 是不可逆动作前的最后闸门**，且是唯一能堵住 `--not-before` 跨过定时时刻的地方：`set_schedule_time` 在 `wait_until_allowed` **之前**（`main.py:1158` → `1164`），等待可能把 FIRE 拖到 `publish_date` 之后；`docs/CLI.md:88` 已写明后果是「平台拒绝或**立即发布**」，但此前无代码断言。C3 把它变成点击前 `exit 1`。
- C2 与 C3 之间没有任何代码会改表单（`wait_until_allowed` 与 ARM 均无点击），C3 只防「迟到重置」和「时效失效」，成本是两次只读属性读取。

### 判据细则

- **解析比较，不要求字符串全等**：平台若规范化（补零/带秒/空格），全等会产生假失败；解析后按分钟比较仍能抓住「回滚到 `now+1h`」。
- **读失败 = 不一致**：节点缺失、`value` 为空、解析异常、读取抛错，一律 `exit 1`（点击前）。定时状态是「设置是否生效」的唯一证据，读不到即无法确认；与 06 的「`probe-failed` 在派发附近阻断」同向，C2 也阻断（回滚后照样会发出去）。
- **不重试**：不一致的根因是平台判定该值非法（或控件没接住），原值重写不会变合法，只会多一遍交互（charter ①）。
- **`--no-publish` 同检查**：干跑的目的正是发现「设置没生效」，不一致 → `exit 1`（与 16 的 Q3「`--no-publish` 跑到 ARM 就绪」一致）。
- **失焦只许 `blur()`**：禁止 Tab / Enter（26：Tab 把焦点交给 `xhs-publish-btn`，Enter 触发「暂存离开」并离开编辑器，两次复现）；也不点空白区（06）。
- **约 300ms 的来源**：26 观察到同类输入组件（标题计数）类名切换在输入事件后 306–344ms，而定时回滚在 `blur` 后即可观察到；取一个**有界短静默**是为了避免「回滚是异步的、立即读读到键入值」的假通过——假通过会按错误时间发布，假失败只是 `exit 1` 重跑，代价不对称。

### 退出码与调用方契约（18 不变）

- 全部发生在点击之前 → **`exit 1`**，`publish_attempted=False`；**不新增码、不产生 `9`、不写回账号文件**。
- 对 18 的契约无新增行：`1` 仍是「确定未发布，可无条件重跑」。

### 对 17 的输入（改写 11 的已知缺口）

- 11 的「已知缺口：定时设置结果不可观测」改写为：**已实现**——开关状态在点击后回读、时间值在 `blur()` 后回读、FIRE 前复核开关/值/时效；不一致 `exit 1`。
- 11 表格中「定时开关 → 无回读」「定时时间 → 无 / 不可检测」两行由本票覆盖；其余行不变。
- 03 的「FIRE 前检查」位增加定时断言（C3），与 07 的页面状态检查并列、互不替代。
- `docs/CLI.md:88` 由「书面提醒」改为「CLI 在 FIRE 前 `exit 1`」（`docs/CLI.md` 是派生投影，权威在 spec）。
- 10 的流程约束「定时时间输入禁止 Enter/Tab」保持，并补一句「失焦只用 `blur()`」。

### 残留风险（规格须保留，不得表述为已解决）

1. **只证明客户端接受，不证明服务端受理**：回读读的是页面模型；服务端在提交时另有规则时，仍按 03/04 的 OBSERVE 判定，本票不新增信号。
2. **平台真实边界未真机验证**：`now+2h` 下界、`now+14d` 上界仍是「上游代码明确 + 待真机」；回读只能发现「页面拒绝」，发现不了「页面接受但服务端另有规则」。
3. **C3 的时效是粗判**：只保证「请求值仍晚于本机现在」，不保证满足平台最小提前量（2h 口径在等待后可能已被侵蚀）。
4. **时钟口径不变**：`publish_date` 与 `now()` 都是本机墙上时间；跨时区调用方的责任同 11，不换算。

### 对 16 的输入

- fake 需支持：`input.value` 读、`blur()` 触发「模型回滚」模拟、`class` 属性读（`.d-switch-simulator`）。回滚可用一个受控 fake 实现（非法值 → `blur` 后返回上次合法值）。
- 断言：正常路径 → `0`；C2 回滚 → `1`；C3 值被迟到重置 → `1`；C3 时效过期（`--not-before` 跨过 `publish_date`）→ `1`；读取抛错 / 空值 / 不可解析 → `1`；`--no-publish` 下同样 `1`；即时发布（`publish_date == 0`）完全不进入本检查。
- 不可离线验证：真实受控组件是否按上述时点回滚、平台真实 2h/14d 边界（前提类，按 16 的 Q2 归真机）。

### 明确不做

- 不做「点击前先读开关、已开则不点」的幂等预读（26 三次采样默认 `unchecked`，每 run 新页面）。
- 不做写后重试、不做多轮轮询、不为定时单独建状态文件。
- 不把该机制抽象进 `utils/`（15 的共享层边界不变；这是小红书表单状态的门闩，不是通用回读框架）。
