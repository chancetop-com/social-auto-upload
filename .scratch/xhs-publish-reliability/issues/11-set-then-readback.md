## Question

决定控件“设置后回读”的覆盖范围与内容校验口径。需要确认：

1. **回读覆盖**：GLOSSARY 定义 `设置后回读`，但小红书只对原创开关做了状态回读（`_switch_is_on`）。定时开关（现直接 click，不判断原状态）、内容类型声明、封面是否补齐？
2. **标题长度**：采用 UTF-16 口径（上游 `CalcTitleLength`：非 ASCII 记 2、ASCII 记 1、`(bytes+1)/2`）还是 Python 码点？超限是**报错**还是截断（现在是静默 `title[:20]`）？CLI 侧是否前置校验。
3. **正文长度**：读 `div.edit-container div.length-error` 的时机（填完立即？发布前？）与失败文案。
4. **定时时间**：下界现 2h、上界无；时区口径（本机 `datetime.now()` vs Profile 时区）如何定义与提示。
5. **失败语义**：回读不一致时是抛错、重试一次、还是降级继续（原创/声明/封面三项现有降级策略是否保留）。

产出：控件 × 设置 × 回读 × 不一致时的动作 三态表 + 长度口径定义。

## Answer

### 决议：本轮采用「上游口径」，不新建通用回读机制

grilling 过程中先定过「选项控件全量回读 + 不符即失败」，看过 `xpzouying/xiaohongshu-mcp` 源码后**主动推翻**，改为与其同构的薄口径（用户决议 2026-11-11）。理由：上游在此处的实际能力只有「原创点击前读一次 + 标题/正文单次 `Has` + 话题轮询 1s」，其余全靠固定 sleep；我们不再自造一套比上游更重的回读循环。

**明确的代价**（已登记为已知缺口，不在本票解决）：定时开关未生效 / 日期被拒时无法检测，可能静默按即时或错误时间发布。这与 charter「禁止对齐下界」冲突，按用户决议接受，取证与重开见 26。

### 控件 × 设置 × 回读 × 不一致动作

| 控件 | 设置动作 | 设置后回读 | 不一致 / 失败动作 |
|---|---|---|---|

退出码：以上失败全部发生在点击发布之前 → **`exit 1`**，不新增退出码、不产生 `9`。

### 标题长度口径（平台口径）

**定义**（上游 `xhsutil.CalcTitleLength` 的等价式，置信度：上游代码明确，平台行为需真机复核）：

```text
weighted = Σ(2 if utf16_unit > 127 else 1 for each UTF-16 code unit)
length   = ceil(weighted / 2)
限制     = length <= 20
```

等价直觉：CJK 每字计 1，ASCII 每字符计 0.5（上限 40），BMP 外字符（emoji）每个代理对计 2。

**行为**：

1. **显式传入的 title** 超限 → `validate_upload_args` 阶段抛 `ValueError`（浏览器未启动）→ `exit 1`。消息含「当前 X / 上限 20」并注明口径。**不截断、不静默**。
2. **自动推导的 title**（`upload-note` 未传 title 时由正文生成）→ 用同一口径逐字符累加，截到 `length <= 20` 再使用，并打 `warning`（生成物不是用户意图）。
3. `fill_title` 删除 `self.title[:20]`，改为填充已校验值。
4. 填充后仍执行 `div.title-container div.max_suffix` 单次检查作为平台侧兜底；元素文案原样入错误，若能拆成 `a/b` 则渲染「当前 a / 上限 b」。

### 正文长度口径

- 时机：正文 + 话题全部输入完成后（话题锚点计入正文长度）**单次**检查 `div.edit-container div.length-error`。
- 判据：**节点存在即失败**（不判可见性、不读计数器数值）。
- 失败：`exit 1`，确定未发布；错误消息含元素文案（可拆 `a/b` 则渲染为「当前 a / 上限 b」，否则整串）。
- 正文**没有**前置预算校验（平台计数规则未取证，无法预检）；漏判风险见「需真机验证」。

### 定时时间口径

- 边界：`now + 2h < publish_date <= now + 14d`。下界保留现状（比上游 1h 更保守）；上界采纳上游（置信度：上游代码明确，平台实际上限**需真机验证**）。越界在 `validate_base_args` 抛错 → `exit 1`，浏览器未启动。
- 时区：**墙上时间语义，不做换算**。naive 按原样格式化；aware 输入**忽略 offset**，按其自带墙上时间格式化（与上游 `t.Format` 一致）。规格需写明「aware 的 offset 被忽略，调用方需自行给出账号时区的墙上时间」。
- 日志：打印最终写入字符串与请求值；**不回读**。
- `--not-before`（`publish_not_before`）不属于本条：它只推迟 FIRE 时刻，仍是即时发布，只校验格式。

### 与上游的对齐 / 偏离记录

| 项 | 上游 | 我们 | 理由 |
|---|---|---|---|
| 标题预检 | 服务层加权 `>20` 报错，不截断 | 同口径，提前到 `validate_upload_args` | 浏览器未启动即失败，更早、代价更低 |
| 标题自动生成 | 无此能力（title 必填） | 按同口径截断 + warning | 本仓 `upload-note` 允许缺省 title，生成物需可落地 |
| 正文长度 | 单次 `Has`，存在即失败 | **完全采纳** | ② 可靠信号，且只读 |
| 原创 true | 点前读、失败中止 | **完全采纳**（读状态用更稳的 `_switch_is_on`） | ① 发成非原创不可逆 |
| 原创 false | 无此能力 | 保留扩展：点前读、点后不读、失败降级 | 关闭是安全默认，不应阻断发布 |
| 定时开关/时间 | 点击/填写 + sleep，无回读 | **完全采纳（含缺口）** | 用户决议；缺口登记，见 26 |
| 内容类型 / 封面 | 上游未实现 | 保留现状：无回读、失败降级 | 无上游参照；能力补齐不属本图 |

### 已知缺口（供 17 汇总进规格）

**定时设置结果不可观测**：开关点击成功但未真正打开、或日期被页面/服务端拒绝时，本链路不会发现，可能按即时发布或按错误时间发布。当前按用户决议接受，属「已知风险」而非「已解决」。若 26 的真机取证证明该缺口真实存在且高频，应重开一票补「点后单次读」。

### 需真机验证（→ 26）

1. `div.title-container div.max_suffix` 是否真实存在、出现时机与文案格式。
2. `div.edit-container div.length-error` 是否真实存在、格式（是否 `a/b`）。
3. 定时开关点击后未生效时，页面是否留下可观测信号（供未来重开）。
4. 原创点击后开关状态是否可稳定读取（本轮不读，但取证决定未来是否值得读）。
5. 内容类型声明 / 封面的可观测回读信号（本轮不读，取证留档）。

### 对其它票的输入

- **15（共享层）**：小红书本轮**不实现**「设置后回读」通用能力，只有原创点击前状态读取；不要把小红书当作该抽象的消费者，避免规格虚增。其它平台的既有回读实现不受影响。

- **17（汇总）**：把「已知缺口」与「需真机验证」原样带入，不得表述为已解决。

## Comments

- **标题锚点由 26 修正（2026-11-11，实机）**：`div.title-container div.max_suffix` 是**死选择器**——现网 `div.title-container` 本身 0 个；真实信号是 `div.edit-container .input > .suffix` 在越限时**改类名为 `max_suffix`**（父容器 `.d-input-wrapper` 加 `c-input_max`），文案 `当前 / 上限`（如 `21 / 20`）。且类名切换发生在输入事件后 **306–344ms**，`fill` 后立即单次检查会漏判 → 本票的「单次存在性检查」需改为**等待/轮询约 500ms** 后再判。正文锚点 `div.edit-container div.length-error` **实测有效**（1000 字 0 命中、1001 字 1 命中），保留不变。
- **「定时设置结果不可观测」缺口由 26 收窄（2026-11-11）**：开关状态可读（simulator class + 日期输入出现/消失）；日期被拒也不是全不可观测——受控组件在**失焦后**把值回滚到上一次合法值（默认 `now+1h`），只是当前流程不主动失焦、也不读，所以仍会按错误时间发布。是否补「失焦 + 单次读」→ **27**（Blocked by: 11, 26）。本票的决议本身不推翻。
- **27 已决议（2026-11-11）：本票的「定时开关/时间 = 无回读」两行被覆盖**——改为点击后读开关、`blur()` 后读时间值、FIRE 前复核（开关 + 值 + 仍 > now），不一致 `exit 1`。详见 [27](./27-schedule-readback.md) 的 `## Answer`。
- **正文计数口径补充（26 实机）**：正文计数器上限 1000；话题锚点**计入**，按 `#name` 计（实测 `#旅行pov[话题]#` → 7，不含 `[话题]#`），且逐字符计数（中文 1=1），与标题的 UTF-16 加权不同。越限时 `xhs-publish-btn@submit-disabled` 仍为 `false`，平台不拦发布 → 点击前检查是唯一闸门。
