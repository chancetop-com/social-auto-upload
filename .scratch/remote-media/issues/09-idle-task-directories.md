# 是否按任务目录的最后修改时间回收闲置七天的素材

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: chancetio (Codex)
Blocked by: 05, 06

## Question

是否以 `downloads/<task-id>/` 的最后修改时间为依据，回收连续七天未使用的任务目录？例如第 1 天预下载、第 10 天才发布，中间没有 CLI 操作，调度 App 是否接受届时重新下载？如果直链已过期，届时需要新的可用链接。

## Comments

- 本机测试中，读取已有文件、向已有的 `.part` 追加字节都没有更新父目录的 `mtime`。在目录中新增文件、直接更新目录时间则会改变它。
- 候选规则：预下载或发布开始使用该 ID 时，以及结束使用并保留目录时，由 CLI 显式更新任务目录的 `mtime`。纯清理扫描跳过排队、下载或发布中的任务，删除前在独占该 ID 时复核空闲状态和时间。这样可以只读一层任务目录，无需遍历每个素材或另存使用时间。[Python 更新文件时间](https://docs.python.org/3/library/os.html#os.utime)
- 平台确认发布成功后立即删除指定目录，省略 ID 的临时发布结束时清理。七天回收只处理这些流程留下的空闲目录。[任务目录清理规则](06-retention.md)

## Answer

调度 App 每天调用一次 `sau media cleanup`。首版使用无参数命令。CLI 扫描 `downloads/` 的直属任务目录，依据本地任务占用状态和目录本身的最后修改时间决定是否删除。

删除必须同时满足以下两个条件。

- 该 ID 没有等待执行的队列请求、正在进行的下载或仍在使用素材的发布命令。
- 距该任务目录的 `mtime` 已满 7 × 24 小时。恰满七天即符合条件，少一秒仍保留。

预下载和发布开始使用目录、以及结束使用并保留目录时，CLI 刷新目录的 `mtime`。扫描本身不刷新它。删除前与队列和发布命令协调，取得该 ID 的独占访问并重新检查占用状态和 `mtime`，两项仍满足才删除整个目录。无法确认是否空闲时跳过。清理范围仅限 CLI 管理的任务子目录，共享队列数据和目录外的文件不参与清理。

调度 App 的排期不会自动延长本地目录的保留时间。例如第 1 天预下载完成、第 10 天才首次发布，中间本地没有活动，这个目录可能已被每日清理回收，发布时需要用有效链接重新取材。
