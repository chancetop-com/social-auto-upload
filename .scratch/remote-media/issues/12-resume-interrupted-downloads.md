# 12: 中断后安全续传

Status: ready-for-agent
Resolution: completed
Blocked by: 11

**What to build:** 调度 App 在下载中断后用同一资源目录 ID 和原 URL 再次等待。CLI 复用磁盘上已经确认写入的字节，只有在能够验证源文件版本和范围时才追加。

规格见[网络素材预下载与上传 CLI 规格](../spec.md)。

## 验收条件

- [x] 从 CLI 启动下载，在取得部分正文后中断，再从新进程调用。用本机源站记录请求，确认恢复时从已持久化的偏移请求同一版本。收到匹配的 `206` 并完成下载后，整个文件的摘要与原件一致。
- [x] 用源站分别返回错误范围、冲突版本、截短正文以及无法验证版本的响应。调用方始终取不到被错误拼接的文件。有效子范围尚未覆盖整份文件时，继续取齐才交付。
- [x] 源站忽略范围或换版并返回 `200` 整份正文时，从零写入。收到 `416` 时，只有已确认的本地全长和版本匹配，或可信摘要能够证明完整，才可交付，否则重新取得整份文件。
- [x] 过期的签名链接报告实际下载错误。首次提交新签名 URL 从头取得新文件，旧 URL 的断点仍属于旧素材。
- [x] 首次下载和续传均让落盘偏移与网络字节表示一致，校验完成后原子交付文件。固定并发和块大小，用两种明显不同大小的文件验证最终摘要，观察内存不会随文件大小成比例增长。

## Comments

本机源站覆盖匹配、换版、错误范围、截断、重定向、签名和 416。独立 CLI 中断后从已写入的第 4,259,840 字节续传，16 MiB 和 128 MiB 文件的 SHA-256 均匹配。最终代码 `b6eb521` 在并发 1 时复测了这两种大小的完整下载，按 60 ms 间隔采样 CLI、调度进程及传输子进程的合计 RSS，峰值分别为 158.4 MiB 和 159.1 MiB。见 `tests/test_remote_media_resume.py`。
