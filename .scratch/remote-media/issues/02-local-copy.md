# 同一 URL 的本地副本什么时候可以复用

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: chancetio (Codex)

## Question

调度 App 为一个 post 预下载的视频，稍后以原 URL 发布时应如何找到同一份本地素材？另一个 post 使用相同 URL、签名发生变化或同一 URL 被覆盖成新内容时，哪些情况可以共用完整文件，哪些需要重新获取？明确完整文件可以交给上传器的条件，以及需要更新时调用方如何表达。

## Answer

所有下载使用项目根目录下的 `downloads/`，布局统一为 `downloads/<任务ID>/`。一个 ID 子目录可以放多个素材。整个下载目录由 Git 忽略，包含指定任务和临时任务的完整文件及断点。[Git 忽略规则](../../../.gitignore)

预下载必须传 `--task-id` 指定子目录，入队即返回和等待完成两种模式都适用。缺少该参数时，在入队或开始下载前报告参数错误。发布命令可选传 `--task-id`。传入时，按资源目录 ID 和素材 URL 查找完整文件或断点。

- 相同 ID、相同 URL：有完整文件时直接使用；正在下载时共用同一份下载；只剩部分文件时在该目录内检查能否续传。
- 相同 ID、不同 URL：分别保存，即使两个 URL 的文件名相同。按完整直链识别时，签名参数变化也会产生不同 URL。
- 不同 ID、相同 URL：在各自的目录中独立下载，完整文件和断点都不跨目录复用。

发布省略 `--task-id` 且需要下载远程素材时，CLI 为本次发布生成一个新 ID，在同一根目录下创建专属子目录。该次发布的所有远程素材及断点都放入此目录。若生成的 ID 已有同名目录，则另取新 ID。无论成功或失败，结束时都删除本次生成的整个子目录，包括下载中断留下的部分文件。调用方传入的本地文件仍归调用方管理。

显式刷新以及签名变更时怎样帮助调用方取回中断素材，见[素材链接或内容变化时怎样刷新](07-refresh-source.md)。带 `--task-id` 的资源目录何时删除，见[哪些本地素材可以清理，由谁触发](06-retention.md)。
