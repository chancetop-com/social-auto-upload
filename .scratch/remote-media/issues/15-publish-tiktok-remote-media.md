# 15: 用原 URL 发布一条 TikTok 视频或图文

Status: ready-for-agent
Resolution: completed
Blocked by: 13

**What to build:** 在 TikTok 的现有发布命令上用原 URL 取材。发布者可以预先入队，也可以直接发布。本地模式和托管浏览器模式都在素材齐备后进入原有上传流程。

规格见[网络素材预下载与上传 CLI 规格](../spec.md)。

## 验收条件

- [x] 通过实际 `sau tiktok upload-video` 验证视频和显式封面可各自来自本地路径或直链。通过 `upload-note` 交错传入本地图片、直链和重复项，离线平台收到的文件内容、顺序和首图均与输入一致。纯本地调用仍可发布。
- [x] 带 `--task-id` 发布时复用该 ID 下的完整副本或进行中的下载。所需素材若已排队，优先于普通预下载，已经开始的其他传输可继续。用源站记录核对启动次序、共享并发上限及同素材的传输次数。
- [x] 省略 ID 且需要远程素材时，每次发布生成未使用的 ID，同次发布共用该临时目录。成功、失败或中断结束时清理整个临时目录，调用方自有本地文件仍可读。
- [x] 有无显式 ID 都从整组必需素材就绪、进入平台上传流程时开始计算 15 分钟发布超时预算。用可控时间令取材超过 15 分钟，验证平台仍获得完整预算。
- [x] 让一张必需图片返回 404，同时另一张尚未完成。发布命令立即退出 `1`，stderr 指明失败项和原因，平台收到零次提交，`publish_attempted=false`。显式指定的目录保留已有文件和断点。
- [x] 从开始用指定 ID 取材（包括等待下载）起，到发布结束释放该 ID 为止，该任务处于发布占用。确认本地及托管入口遵守相同的取材、失败和计时约定。

## Comments

离线 TikTok 发布覆盖混排、重复项、视频和封面。取材推进 18 分钟后平台仍可用 15 分钟预算。验证了失败项先报告、零提交、临时目录回收以及进程被终止时的处理。见 `tests/test_remote_media_publish.py`。
