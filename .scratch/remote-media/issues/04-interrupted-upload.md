# 素材下载中断后怎样恢复并报告结果

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: chancetio (Codex)
Blocked by: 01, 02, 03

## Question

调度 App 已经打断预下载，随后以同一资源目录 ID 和原 URL 调用发布。文件已就绪则复用，有可用的断点则续传，服务器忽略 Range 时从头分块下载。若发布时改传另一个 ID，则只查新目录。当一组素材只有部分就绪时，除了退出码，调度 App 如何获知各素材的下载结果？省略 ID 的临时发布是否采用同样的计时和失败约定？

## Comments

- 已确认带 `--task-id` 的发布命令先取得该 post 所需的全部素材。本次下载、接续断点以及等待已有下载完成，都发生在 15 分钟发布预算开始之前。即使取素材用了 18 分钟，进入平台上传流程时仍有完整的 15 分钟预算。[发布超时预算](../../../GLOSSARY.md#发布超时预算)
- 任一必需素材最终下载失败，发布命令退出 `1`，此时尚未提交 post（`publish_attempted=false`）。保留任务目录内已完成的文件和可用断点。[任务目录清理规则](06-retention.md)

## Answer

预下载中断后，以同一 `--task-id` 和原 URL 发布时，CLI 复用完整文件，等待仍在进行的下载，或从经过校验的断点续传。如果源站忽略范围请求并返回整份文件，就从头分块写入。改传另一个 ID 时，只在新 ID 对应的目录查找。[入队返回后由谁下载，发布命令怎样接手](05-download-queue.md)

发布命令一旦发现任一必需素材下载失败，立即向 stderr 输出错误信息，以 `1` 退出。例如发布三张图片，第二张下载返回 HTTP 404，此时即可报告“第 2 张图片下载失败（HTTP 404）”并退出，无需等第三张。平台上传流程尚未开始，`publish_attempted=false`。调度 App 需要整组逐项结果时，可调用 `sau media predownload --wait`。[预下载命令怎样返回入队结果或本地路径](03-predownload-cli.md)

传入或省略 `--task-id` 都采用上述失败约定。两种调用都在整组必需素材就绪、进入平台上传流程时开始计算 15 分钟预算。发生下载失败时，显式指定的任务目录保留完整文件和可用断点，省略 ID 时生成的临时目录在命令结束时删除。[哪些本地素材可以清理，由谁触发](06-retention.md) · [同一 URL 的本地副本什么时候可以复用](02-local-copy.md)
