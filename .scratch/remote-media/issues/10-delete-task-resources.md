# 如何按任务 ID 直接删除本地素材

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: chancetio (Codex)
Blocked by: 05, 06

## Question

调度 App 怎样删除整个任务目录或其中一个素材？当该 ID 仍有排队、正在写盘的预下载，或者发布命令仍在使用其素材时，删除和正在运行的命令分别收到什么结果？

## Answer

`sau media delete --task-id ID [--url URL]` 每次接受一个必填的任务 ID，对目录年龄没有要求。

| 调度 App 的命令 | 删除范围 |
| --- | --- |
| `sau media delete --task-id post-42` | 删除整个 `downloads/post-42/`，包括全部完整文件和下载断点。 |
| `sau media delete --task-id post-42 --url "$url"` | 按预下载时的完整 URL（含签名参数）定位一个素材，删除它的完整文件和断点。保留任务目录及其中的其他素材。 |

缺少 ID 或用路径充当 ID 时按参数错误处理。目标须位于资源根目录下指定的直属任务目录，禁止沿符号链接删除其他位置的文件。

两种删除都先检查整个任务的发布占用。从发布命令开始用该 ID 取材（包括等待下载）直到它释放该 ID，都算占用，即使发布只用到了目录中的其他素材。此时删除命令立即退出 `1`，向 stderr 写一行错误消息，例如 `任务 post-42 正在发布，请稍后再试。`。目录和预下载队列均保持原状。

取得删除权后，CLI 先撤下删除范围内已排队的下载（包括尚未创建文件的下载），取消正在进行的传输，等写入者停止后再删除文件。删除单项时，同一任务下其他 URL 的排队或下载照常进行。后台进程重启时也不能恢复已撤销的请求。[入队返回后由谁下载，发布命令怎样接手](05-download-queue.md)

整目录删除时，正在等待该任务的预下载命令收到 `task_cleared`。单项删除时，正在等待该 URL 的预下载命令将对应项记为 `reason="item_deleted"`，继续等待其余素材。整组结束后按输入顺序返回结果，退出 `1`。[预下载命令怎样返回入队结果或本地路径](03-predownload-cli.md)

占用检查与取得删除权按同一 ID 互斥。发布先取得使用权时，删除立即返回占用。删除先取得删除权时，后到的新请求等删除结束后再使用该 ID。其他 ID 的任务照常运行。

删除成功时静默退出 `0`，包括指定素材或目录已经不存在且没有待撤销下载的情况。失败时退出 `1`，仅向 stderr 写一行说明原因的纯文本，包括发布占用、缺少或传错 `--task-id`、删除文件失败等情况。[发布成功清理](06-retention.md) · [每日闲置目录清理](09-idle-task-directories.md)
