# 哪些本地素材可以清理，由谁触发

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: chancetio (Codex)
Blocked by: 02

## Question

这里讨论带 `--task-id` 的资源目录。一个目录可能给多个 post 使用，其中一个已发布，另一个还在排期或等待重试。是否按整个 ID 清理，由调度 App 显式释放，还是也需要其他回收方式？区分正在使用的文件、待续传的部分文件以及已返回给调用方的路径。省略 ID 时的清理时机已在[同一 URL 的本地副本什么时候可以复用](02-local-copy.md)中确定。

## Comments

- 讨论建议：先保证一次发布结束不会误删下一条 post 或重试要用的素材。如果排期中的 post 需要保证离线可用，可由调度 App 标记它仍在用哪些素材；若只需尽力复用，可采用更简单的显式清理。候选清理范围限于 CLI 管理的下载目录，调用方自行传入的本地文件归调用方管理。自动清理的期限和容量尚待决定。

## Answer

发布命令传入 `--task-id` 时，平台确认该 post 发布成功后，由 CLI 直接删除整个 `downloads/<task-id>/`，包括这个目录内的其他素材和断点。调度 App 无需再发释放命令。清理范围仅限本次指定的子目录。

预下载完成、发布失败、发布中断、发布结果未知或使用不发布模式时，都保留指定目录。判定依据是平台发布流程的结果，单凭命令退出码为 `0` 不能触发清理。发布结果未知时保留文件供核查，重发仍遵循现有发布契约。[不发布模式](../../../GLOSSARY.md#不发布模式no-publish) · [发布结果未知](../../../GLOSSARY.md#发布结果未知)

发布时省略 `--task-id` 的临时目录继续采用[临时下载的清理规则](02-local-copy.md)，发布成功或失败都会删除。

调度 App 可以[按任务 ID 主动删除保留的资源](10-delete-task-resources.md)，也可以通过[每日清理](09-idle-task-directories.md)回收闲置目录。
