# 网络素材预下载与上传 CLI 规格

Status: ready-for-agent
Resolution: completed

## Problem Statement

调度 App 收到一条 post 时，拿到的往往是视频、图片或封面的 HTTP(S) 直链，现有发布命令接收的是本地文件。App 可能提前几天拿到链接，也可能在素材只下载了一半时退出。到发布时，它需要知道哪些文件可以直接用、哪些可以接着下，以及下载失败时帖子是否已经提交。大视频还可能超过机器的可用内存。

## Solution

调度 App 可以在收到 post 时单独预下载，也可以到发布时直接传原 URL。两次命令使用相同的 `--task-id` 和完整 URL，就能接着用之前的下载。独立预下载默认返回入队回执，加 `--wait` 则返回每个输入的结果。发布命令先取得整组素材，再把完整本地文件交给现有平台上传器。

例如，App 收到两张图时可以先入队，随后直接用原 URL 发布。若中间需要拿到本地路径，可先用相同的 ID 和 URL 再调用一次预下载，加上 `--wait`。

```sh
sau media predownload --task-id post-42 --urls 'https://cdn.example.com/a.jpg' 'https://cdn.example.com/b.jpg'
sau tiktok upload-note --account demo --task-id post-42 --images 'https://cdn.example.com/a.jpg' 'https://cdn.example.com/b.jpg'
```

项目根目录下的 `downloads/<任务ID>/` 是这些命令共用的资源目录。预下载返回的绝对路径可直接用于现有发布参数，其可用期限取决于该任务目录的清理时机。

## User Stories

1. 作为调度 App，我希望收到 post 后就能提交一组直链，以便先处理其他任务，让素材在后台下载。
2. 作为调度 App，我希望在需要本地文件时等到本批下载结束，以便按原输入位置分别取得路径或失败原因。
3. 作为调度 App，我希望收到入队回执后能用同一资源目录 ID 和原 URL 直接发布，以便省去轮询和路径转换。
4. 作为发布者，我希望视频、图片和平台支持的自定义封面都可来自本地或直链，以便沿用各平台现有的发布命令。
5. 作为图文发布者，我希望本地图片和网络图片可按任意顺序混排，以便首图和后续图片都出现在指定位置。
6. 作为调度 App，我希望重复输入同一个 URL 时只下载一次，同时保留每个输入位置，以便逐项对应原始素材清单。
7. 作为同时处理多条 post 的调度 App，我希望同名文件和不同任务各自独立，以便一条 post 的内容或清理动作不会影响另一资源目录。
8. 作为调度 App，我希望中断等待后还能用已完成的文件和有效断点，以便减少重传，并让其他命令仍需要的下载继续。
9. 作为发布者，我希望临近发布的素材能优先取得下载名额，以便排在队列中的普通预下载不会一直挡住发布。
10. 作为运营者，我希望大视频能分块落盘，并能限制同时下载的文件数，以便按机器资源安排下载。
11. 作为发布者，我希望源文件换版时仍能拿到一份完整、版本一致的文件，以免把两个版本的字节拼在一起上传。
12. 作为调度 App，我希望签名过期时知道源站返回的错误，并能提交新链接，以便恢复取材。
13. 作为发布者，我希望整组素材就绪后才开始计算发布超时预算，以便慢速下载仍能给平台上传留足 15 分钟。
14. 作为调度 App，我希望发布遇到第一份取不到的必需素材时就报告它，以便明确帖子尚未提交。
15. 作为偶尔直接发布的用户，我希望省略任务 ID 也能上传远程文件，以便命令结束后自动释放这次下载的空间。
16. 作为调度 App，我希望确认发布后自动清理整个任务目录，而在失败、仅验证或发布结果未知时保留指定目录，以便核查并继续使用素材。
17. 作为调度 App，我希望能单独删除一张已换版的图片，也能撤销整个任务，以便控制重新下载的范围。
18. 作为运营者，我希望每天用一条命令回收闲置满七天的任务，以便释放磁盘并保护正在排队、下载或发布的素材。

## Implementation Decisions

### 命令与预下载回执

| 命令 | 调用约定 |
| --- | --- |
| `sau media predownload --task-id ID --urls URL [URL ...] [--wait]` | 两种模式均必填 ID 和至少一条 HTTP(S) 媒体直链，支持签名链接。整批参数校验通过才入队。 |
| `sau <平台> upload-video`、`sau <平台> upload-note` | 在现有命令上增加可选的 `--task-id`。`--file`、`--images` 和该平台已有的 `--thumbnail` 接收本地路径或直链。图片按输入顺序交付，包括重复位置。现有平台的文件类型、数量、账号和发布选项约束继续适用。 |
| `sau media delete --task-id ID [--url URL]` | 删除一个完整 URL 的素材或整个任务目录。 |
| `sau media cleanup` | 无参数。由调度 App 每天调用一次，回收闲置目录。 |

预下载的标准输出供程序读取，每次有结果时只写一个 JSON 对象，含调用方的 `task_id`。日志和诊断写入标准错误。

| 预下载结果 | 退出码 | 调用方看到的输出 |
| --- | --- | --- |
| 默认模式，请求已持久化且后台进程已接手 | `0` | `{"task_id":"post-42","status":"accepted"}`。此时文件可能尚未就绪。 |
| 等待后全部就绪 | `0` | `status="ready"`，`items` 按输入顺序为每一项给出绝对 `path`。重复的 URL 在每个位置都有结果。 |
| 等待时有素材失败 | `1` | 继续其余项，整组结束后返回 `status="failed"`。成功项给出 `path`，失败项给出 `reason`，例如 `HTTP 404`。 |
| 等待的单项被显式删除 | `1` | 对应位置给出 `reason="item_deleted"`，其余项继续，最终按整组失败返回。 |
| 等待的整个任务被清理，包括确认发布后清理 | `1` | 立即结束等待，返回 `status="task_cleared"`、`items=[]`。 |
| 队列持久化或后台进程启动失败 | `1` | `status="failed"`、顶层 `reason="queue_unavailable"`、`items=[]`。 |
| 参数或配置无效 | `2` | 入队前退出，诊断仅写标准错误。 |
| 用户按 Ctrl-C 中断 | `130` | 调用方按退出码处理中断，无需解析 JSON。 |

### 文件归属、复用与刷新

- 素材由资源目录 ID 和完整 URL 共同标识，签名参数参与匹配。一个目录可保存多份素材。同名但 URL 不同的文件分别保存。同一 URL 在不同 ID 下独立下载。CLI 管理的下载根目录及断点由 Git 忽略。
- 同一 ID 和 URL 已有完整文件时直接复用，即使源站已替换内容。有写入者时共用同一次传输，只剩断点时先检查是否可续传。已知内容需要刷新时，先按该 URL 删除，成功后再取材。
- 签名过期时报告源站实际错误，例如 HTTP 403。首次提交新签名 URL 时从头下载。旧 URL 的断点留到按旧 URL 删除或整个目录清理。
- 发布省略 ID 且包含远程素材时，CLI 生成一个未被使用的 ID，遇到同名目录就另取一个。本次远程素材共用该目录，命令结束时将其整体删除，包括失败或中断留下的部分文件。调用方提供的自有本地文件由调用方管理。

### 下载队列与断点

- 同一资源根目录下的预下载和发布取材共用持久化队列及独立的后台下载进程。`SAU_DOWNLOAD_CONCURRENCY` 接受正整数，默认 `1`。上限跨命令、跨 ID 生效。后台进程启动时读取配置，修改值在下次启动时生效。无效配置按预下载参数错误处理。
- 默认入队返回后，App 退出，后台仍继续下载，队列清空后进程自行退出。终止一个正在等待的预下载 CLI 时，撤下只有该请求需要的排队项，停止其独占传输并保留断点，其他命令仍需要的素材继续下载。
- 发布需要的已排队素材优先于普通预下载，已开始的传输继续。后台进程意外退出时，仍在等待的命令会立即拉起新进程。无人等待时保留队列和断点，下次取材时恢复。多个命令共同恢复时，同一份文件只允许一个写入者。
- 下载首选项目已有的 Requests。整个传输链路须有界读写，包括首次下载、续传、重定向响应和文件校验。每个活动下载只保留固定大小的正文缓冲，内存随并发度和块大小增长，大文件无需整体载入。
- 在磁盘上区分已确认的连续字节和可交付的完整文件。续传请求使用已确认偏移和能证明同一版本的校验信息。仅在 `206` 的版本、字节范围及实收长度匹配时追加。缺少可靠版本依据时重新下载。源站返回 `200` 整份文件时从零写入。遇到 `416`，须确认本地覆盖全长且版本一致，或通过可信摘要确认完整，否则重新获取整份文件。保证网络传输和落盘偏移使用同一字节表示。校验通过后再原子地交付最终文件。

### 发布取材与结果

- 各平台共用取材行为。先解析本次发布显式提供的全部素材，包括封面，保留图文输入顺序，再将可用本地路径交给平台原有的校验和上传流程。本地模式与托管浏览器模式使用同一规则。
- 任一必需素材下载失败，立即向标准错误说明哪一项失败及原因，退出 `1`。例如三张图中第二张返回 HTTP 404，就可以当场报告。此时平台上传尚未开始，`publish_attempted=false`。需要整组逐项报告的调用方可使用预下载的等待模式。
- 显式 ID 和临时 ID 的发布超时预算均从整组必需素材就绪、进入平台上传流程时开始。排队、下载、断点恢复和等待现有写入者都在预算之前。即使取材花了 18 分钟，平台仍有完整的 15 分钟预算。

### 确认发布、主动删除与闲置清理

| 情形 | 指定资源目录 ID 的处理 |
| --- | --- |
| 平台确认 post 发布成功 | 使同一 ID 的旧队列请求失效，取消剩余传输并等写入者停下，再删除整个任务目录。即使只发布其中两张图，也清理目录内其余素材和断点。之后明确提交的新请求可再次使用该 ID。 |
| 预下载结束，或发布失败、中断、结果未知、使用不发布模式 | 保留完整文件和可用断点。不发布模式成功退出 `0` 也要保留。发布结果未知沿用退出码 `9`，须先核查帖子。 |
| 主动删除 | 必填单个 ID，可按一个完整 URL 将范围缩小到该项，保留目录和其他素材。整目录删除包括所有完整文件、断点和待执行请求。两种删除均无目录年龄限制。 |
| 每日清理 | 只扫描 CLI 管理的直属任务目录。没有排队、下载或发布占用，且目录自身 `mtime` 已满 `7 × 24` 小时，才删除整个目录。共享队列数据和目录外的文件均受保护。 |

- 主动删除先检查整个 ID 的发布占用，从发布取材开始（含等待下载）一直覆盖到释放 ID。即使要删的是另一张图，只要发布已占用就立即退出 `1`，队列和文件保持原状。若删除先获得独占访问，后到的新请求等它结束再用该 ID，其他 ID 照常运行。
- 取得删除权后，先撤下范围内的排队项（包括还没建文件的请求），停止传输并等写入者退出，再删除文件。已撤销请求在后台进程重启后也不能重建素材。单项和整目录删除分别按预下载回执中的 `item_deleted`、`task_cleared` 通知等待方。
- 主动删除成功时静默退出 `0`，目标已经不存在且没有待撤销请求时同样成功。缺少 ID、将路径当作 ID、发布占用或删除失败时均退出 `1`，仅向标准错误写一行原因。删除范围限定在指定直属任务目录内，不能沿符号链接删除其他位置的文件。
- 预下载或发布开始使用目录、结束使用并保留目录时，显式刷新目录自身的 `mtime`。清理扫描不刷新时间。删除前取得该 ID 的独占访问并复核空闲状态和时间，无法确认空闲就跳过。恰满七天可删，少一秒仍保留。App 的未来排期不延长保留期。

## Testing Decisions

验收从调度 App 实际调用的 `sau` 命令进入，在本机完成。用可控制的 HTTP 源站提供已知内容、记录请求并制造断线或换版，用临时资源目录承载多次命令的真实文件，用已有离线平台夹具记录平台收到的文件和提交次数。已有的 YouTube 共享会话 CLI 测试提供了子进程、离线站点和提交记录的先例，小红书发布预算测试提供了推进虚拟时间的先例。

| 验收场景 | 可从命令外部核对的结果 |
| --- | --- |
| 入队、等待与失败 | 源站暂缓发送正文，首个 CLI 应能在后台接手后返回 `accepted` 并退出。放行正文后，以同一 ID 等待应能取得正确文件。混入重复 URL 和 404，核对输入位置、逐项路径或原因、标准输出与错误分流及退出码。分别覆盖无效参数、无效并发配置、队列不可用和 Ctrl-C。 |
| 断点与大文件 | 在已写入部分字节后中断，从另一进程恢复。源站分别给出匹配范围、忽略范围、换版、错误范围和 `416`。核对请求偏移与最终文件摘要，确保半成品从未交给上传器。在相同并发和块大小下扩大文件，验证内存不会随文件大小成比例增长。 |
| 身份与换版 | 用同 ID 的同名不同 URL、不同 ID 的同 URL 和同 ID 的新签名分别下载。核对请求次数、文件内容、过期错误及旧断点归属。源站覆盖内容后仍可复用完整副本，单项删除后能取回新版。 |
| 多进程共享队列 | 在名额已占用时排入普通预下载和发布请求，观察源站的并发峰值和下一份开始传输的素材。中断一个等待者或后台进程，覆盖有、无其他等待者两种情况。检查共享下载只传输一份，独占传输可恢复，已撤销的请求不会复活。 |
| 平台交接与预算 | 对各平台已有的素材参数核对覆盖面。在离线发布中观察纯本地输入、混排图片、视频和封面的文件内容及顺序。让取材耗时超过 15 分钟，验证仍可按平台预算完成。再让一项返回 404、另一项持续等待，核对发布立即退出 `1`、指出失败项、平台收到零次提交。 |
| 发布后的目录归属 | 分别模拟确认成功、上传失败、中断、发布结果未知和不发布模式。核对指定目录和临时目录是否按约定清理，调用方自有文件仍可读。发布只用目录内部分素材时，检查其他等待者收到 `task_cleared`，后台恢复后旧目录不会重建。 |
| 删除与七天边界 | 跨进程交错执行发布、单项删除和整目录删除，核对占用、等待者结果、重复删除及范围外文件。把目录时间设在恰满七天和少一秒处，分别覆盖闲置、排队、下载、发布占用及扫描后重新使用的情况。 |

验收依据是调用方读到的输出、退出码、可用文件、源站收到的请求和平台收到的提交。队列表结构、锁文件名称及内部函数调用次数属于实现细节。

## Out of Scope

- 解析社交平台分享页以发现媒体地址。首版输入限于直接返回媒体文件的 HTTP(S) 链接。
- 从本地向发布平台上传文件时的断点续传。
- 调度 App 隔日是否重跑、何时重跑及选择哪条命令。CLI 提供每次调用的结果，调度策略由 App 决定。
- 独立状态查询命令和 `--refresh` 参数。已有的等待调用和按 URL 删除分别满足查询结果、主动更新内容的需求。

## Further Notes

调度 App 若要分别保留两条 post 的素材，应使用不同的资源目录 ID。一个 post 确认发布会清理该 ID 下的全部素材，即使发布命令只选了其中一部分。提前排期超过七天的 post 也要考虑本地副本已被回收，届时发布需要仍然有效的直链。
