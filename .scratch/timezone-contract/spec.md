# 时区契约（--schedule / --not-before）

## 目标

让调度后端只传 UTC 零偏移的绝对时刻，CLI 负责把绝对时刻换算成平台控件需要的墙上时间，并移除所有写死的北京时间假设。

## 契约

- `--schedule`：UTC ISO 8601 绝对时刻（零偏移，`Z`/`+00:00` 等写法均可；秒/微秒必须为 0），例如 `2026-11-12T10:30:00Z`。填写平台控件前，从页面读取实际浏览器时区（`Intl.DateTimeFormat().resolvedOptions().timeZone`）并换算；读取失败退出 `1`，不回退到进程时区。
- `--not-before`：UTC ISO 8601 绝对时刻（零偏移，`Z`/`+00:00` 等写法均可；必须用 `T` 分隔，保留秒级精度、不接受小数秒），例如 `2026-11-12T10:30:00Z`。CLI 只收零偏移；Python API 的 `publish_not_before` 仍接受任意 aware 时刻。解析后换算到运行机器的本地时区再等待/打印。
- 无时区、非 UTC 偏移或空格分隔的输入不再接受。
- 不做“输入 offset 是否等于浏览器时区”的校验。

## 非目标

- 不实现 YouTube 定时发布；传入 `--schedule` 退出 `2`。
- 不在 CLI 内写死 `Asia/Shanghai`；托管模式由 Profile 决定浏览器时区。

## 平台差异

- Bilibili 直接把绝对时刻映射为 `--dtime` epoch，不读取页面时区。
- 其余支持 `--schedule` 的浏览器平台在填写前读取页面时区。
- 平台窗口（2 小时、7 天、5 分钟档、30 分钟、48 小时、14 天等）仍按绝对时刻校验。
