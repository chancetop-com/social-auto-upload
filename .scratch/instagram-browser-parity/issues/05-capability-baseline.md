# 05 — 目标能力基线与逐项取舍

Status: resolved
Type: grilling
Blocked by: 04

## Question

基于 04 的能力矩阵，与用户确认：

- 基线取并集、交集，还是以 Business 为主。
- 每项能力纳入实现、延后、还是明确排除。
- 对“API 支持但网页端无入口”的能力，采用跳过、替代入口（如 Business Suite）、还是明确排除。
- 哪些能力需要真实账号实测后才能定。

## Answer

用户拍板（2026-11-10）：

- **基线**：网页可达并集，不按两套 API 的交集自砍；API-only 项明确标 `unsupported`。
- **第一波实施范围**：价值排序 1–10，**排除 #3「媒体校验（大小/时长/宽高比）」**。纳入：
  1. Stories（图/视频）
  2. 定时发布
  4. location
  5. 关闭评论
  6. 配乐 / 曲库
  7. 选帧封面
  8. user_tags
  9. alt_text
  10. AI 生成标识
- **本轮不做**：媒体校验（#3）。第二波 11–20 按账号需求再启动；第三波 21–25 延后。
- **待确认**：`发布后回读对账`（可靠性基础，未在价值排序表中单列）是否随第一波一起做。
- **未决**：Stories/配乐/定时的网页入口需真实账号实测；入口缺失或账号资格不满足时按 `unsupported` 处理，不当作失败。
