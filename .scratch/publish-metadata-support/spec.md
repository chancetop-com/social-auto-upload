# 发布命令的 AI 声明、帖子地点与配文话题

Status: ready-for-agent

## Problem Statement

作者要求给帖子加上 AI 声明、选中一个地点，或把话题写在一句话的特定位置。现有 CLI 的成功结果不足以回答三个问题：页面最终选了什么、配文是否还是原稿、这条命令在哪种帖型和账号上验过。小红书可以在 AI 声明设置失败后继续发布，Instagram 曾把被确认框遮住的开关记作入口缺失。地点候选还可能同名而地址不同。

旧参数 `--tags` 也使作者难以预测哪些词会公开。它在一些平台把词追加到配文末尾，在 YouTube 却把词送到 Studio 后台关键词栏。调用方需要在上传前知道旧写法已经失效，并能明确选择要公开的词。

## Solution

小红书、Rednote、Instagram 和 TikTok 的视频与图文命令都支持按名称请求帖子地点，沿用各平台已有的 AI 声明参数。上传器在点击发布前完成设置后回读。调用方从现有命令输出中看到请求值、页面终值，以及继续或停止的原因。

七个平台的十三条媒体发布命令统一从最终公开配文识别 `#话题`。作者直接决定话题的位置和标点。支持关联的编辑器逐词报告关联结果，所有入口核对作者将要公开的全文。CLI 文档按八条命令分别给出三类元数据的网页证据、CLI 已接入行为和实测账号。

## User Stories

1. 作为小红书或 Rednote 作者，我希望用既有的 `--content-type ai` 声明 AI 内容，以便确认视频或图文确实选中了该内容类型。
2. 作为 TikTok 或 Instagram 作者，我希望能省略、开启或关闭 AI 声明，以便沿用网页当前设置或明确指定这次发布的状态。
3. 作为作者，我希望在上传前发现互斥的声明，以便修正请求后再提交素材。
4. 作为调度方，我希望区分开关已关、入口确实缺失和编辑器被遮挡，以便判断帖子能否继续发布。
5. 作为作者，我希望按地点名称搜索，以便跳过排在前面的近似建议。
6. 作为运营者，我希望看到第一个同名地点的候选地址和选中后的名称，以便核对这次实际选中了哪个地点。
7. 作为小红书或 Rednote 作者，我希望分别填写帖子地点和自主拍摄声明的拍摄地点，以便两项信息各自进入正确的控件。
8. 作为作者，我希望在找不到所需地点或无法确认选中时停在发布前，以便修正地点后再发。
9. 作为作者，我希望直接在配文中写入话题，以便保留顺序、重复、换行和紧邻话题的标点。
10. 作为作者，我希望带片段的链接原样保留，以便网址中的 `#` 片段不会触发话题选择。
11. 作为小红书、Rednote 或 TikTok 作者，我希望命令在原位置点选同名话题，包括「新建话题」和 `Add`，以便在全文中核对对应关联。
12. 作为作者，我希望无同名候选或达到关联数量上限时保留原词并看到原因，以便在配文完整时照常发布。
13. 作为作者，我希望在错选话题、配文被改写或触及整帖硬限制时收到错误，以便自己决定怎样改稿。
14. 作为旧脚本的维护者，我希望十三条命令一致拒绝 `--tags` 并提供迁移示例，以便显式选择哪些词写进公开配文。
15. 作为 YouTube 或 Facebook Page 作者，我希望公开话题与后台关键词分别维护，以便原有关键词和独立标题保留作者填写的值。
16. 作为调用方，我希望继续使用 Instagram 的结果文件和其他平台的终端输出，以便已有任务仍能识别准备完成、发布前失败和提交结果。
17. 作为验收者，我希望用不发布模式核对各帖型的字段终值，并看到实测账号、语言和阶段，以便判断证据适用于哪个发布入口。

## Implementation Decisions

### 命令范围

下表每行对应一条 `sau` 命令。八条命令都支持 `--location TEXT`。CLI 文档用相同的八行分别记录每个字段的网页证据、当前版本的 CLI 行为和账号样本。

| 发布命令 | AI 声明参数 | 配文话题在发布前的验收位置 |
| --- | --- | --- |
| `xiaohongshu upload-video` | `--content-type ai` | 视频正文的同名话题锚点与全文 |
| `xiaohongshu upload-note` | `--content-type ai` | 图文正文的同名话题锚点与全文 |
| `rednote upload-video` | `--content-type ai` | 视频正文的同名话题锚点与全文 |
| `rednote upload-note` | `--content-type ai` | 图文正文的同名话题锚点与全文 |
| `instagram upload-video` | `--ai-generated` / `--no-ai-generated` | Reel 编辑器的完整配文 |
| `instagram upload-note` | `--ai-generated` / `--no-ai-generated` | 图片帖编辑器的完整配文 |
| `tiktok upload-video` | `--aigc` / `--no-aigc` | `--title` 是视频配文，核对原位话题标记与全文 |
| `tiktok upload-note` | `--aigc` / `--no-aigc` | Photos 正文取 `--note` 或既有的正文文件输入，核对原位话题标记与全文 |

### AI 声明

- 省略参数时保留页面当前值，包括原本已开启的开关。显式开启需从编辑器读到创作者选定的声明。平台自动添加的标识不能作为这次请求的回读。
- 小红书与 Rednote 在菜单收起后核对「笔记含AI合成内容」。缺少该项、终值为空或显示其他内容类型，均在发布前失败。两端的内容类型都是单选，沿用原生参数名。独立的 `--original` 可与 AI 声明并用。
- 显式要求互斥值，在上传前按用法错误退出 `2`。这包括同时要求开启与关闭，以及重复传入不同的内容类型，如 `ai` 和 `marketing`。
- TikTok 与 Instagram 显式关闭时，可见开关已关可继续，从开切到关后须回读。可操作的编辑器中确认入口缺失也可继续，结果记 `default_off`、原因 `entry_missing`，终值未知。开关可见但禁用且仍为开，或读不到可见开关的状态，都须停止。

### 帖子地点

- 省略 `--location` 时保留页面原值。显式传空串或纯空白在上传前退出 `2`。小红书与 Rednote 的 `--shoot-location` 继续填写自主拍摄声明。
- 以候选行里的完整**名称**作比较，忽略大小写，去掉首尾空白并合并连续空白。按页面顺序点选第一个同名候选。比如搜索「人民公园」时跳过「房山人民公园」。有多个「人民公园」时记录所点行的可见地址，即使控件收起后只显示名称。
- 成功须同时满足候选列表已收起、控件显示所选名称。报告请求名称、所点行的名称及可见地址、收起后读到的名称。无地址时只记录能看到的值。
- 空列表或只有近似候选时报无匹配。入口缺失、页面明确提示资格限制、列表未收起、终值缺失或不符，都须区分原因并停在发布前。只有页面明确提示资格限制才可报告「账号不可用」。

### 配文话题与旧参数迁移

- 八条命令以及 `facebook`、`facebook-page` 各自的 `upload-video` / `upload-note` 和 `youtube upload-video` 均移除 `--tags`。传入旧参数时由命令解析器退出 `2`。既有的正文和正文文件输入继续进入同一套最终配文处理。
- 从最终公开配文按出现次序识别每一处 `#话题`。原位保留重复词、换行、空格、标点及链接。网址中的 `#片段` 保留在网址内。延续各命令既有的标题和正文组合方式。YouTube 只从简介识别话题，独立标题中的词不计入结果。Studio 后台关键词及 Facebook Page Reel 独立关键词栏保留页面原值。
- 小红书、Rednote、TikTok 的六个编辑器逐词选同名行，包括「新建话题」和 `Add`。在正文中从锚点或话题标记读到对应名称后才报告「已关联」。核对全文时按原词读取话题节点，保留节点外的每个字符。编辑器自动追加的空格如与原稿不符，应移除并再次确认关联和标点。
- 无同名候选或已达可关联数量上限时，原位保留文字并逐处报告原因。例如小红书的第 11 个话题仍须完整可读。只能确认文字时按文字报告。Instagram、Facebook 个人主页、Facebook Page 核对完整公开配文，YouTube 核对简介全文。
- 全文逐字一致才可放行。吞字、错位、重复追加、错选关联或整帖硬限制均须停止并指出差异或限制，由作者改稿。
- 迁移示例：原调用片段 `--note '今天喝了咖啡，配上栗子蛋糕。' --tags 咖啡,栗子蛋糕` 改为 `--note '今天喝了 #咖啡，配上 #栗子蛋糕。'`。若「咖啡」关联成功而「栗子蛋糕」只有近似候选，结果依次报告「已关联」「保留文字，无同名候选」。原先仅给 YouTube 后台使用的词，由调用方自行决定是否写入简介公开。

### 设置后回读与调用方结果

- 元数据校验接入各平台已有的发布前流程。浏览器操作通过现有的人类化交互层完成，控件定位限定在当前可操作的编辑器、菜单或候选行；每步等待所需的页面状态，包括关闭人类化时。字段未通过验收时停止，最终发布按钮点击次数为零。
- 每个字段报告请求值、页面终值、是否可继续及失败或降级原因。省略的可选字段记为未请求，未观察到的值不得推定。配文话题的逐词结果保留出现顺序和重复次数。
- Instagram 沿用成功时的 JSON 输出、默认结果文件、`--result PATH`、既有 `options` 字段和顶层发布状态。新增证据以兼容方式追加。小红书、Rednote 和 TikTok 的六条命令从现有终端诊断及退出码报告，保留原成功摘要。

| Instagram 显式关闭 AI 时的现场 | AI 选项与发布结果 |
| --- | --- |
| 可见且原本已关 | `requested=false`、`applied=false`、`status=default_off`，其他字段通过即可继续 |
| 从开切到关并读回 | `applied=false`、`status=set`，其他字段通过即可继续 |
| 可操作的编辑器中确认入口缺失 | `applied=null`、`status=default_off`、`reason=entry_missing`，其他字段通过即可继续 |
| 「放弃帖子？」在前台，最终无法读取被遮挡的编辑器 | `applied=null`、`status=mismatch`，说明遮挡原因，顶层 `not_submitted`，退出 `1`，Share 点击零次 |

## Testing Decisions

以调用方执行的 `sau` 发布命令为主测试入口。观察退出码、终端或结果 JSON、编辑器实际终值，以及是否派发最终发布动作。受控编辑器复现同名排序、入口缺失、读值相反和弹窗遮挡；真实账号用 `--no-publish` 停在发布前。断言用户可观察的结果，具体选择器、助手函数调用顺序和等待时长由实现决定。

| 验收顺序 | 最小可复验场景 | 通过条件 |
| --- | --- | --- |
| 1. 命令与 AI 声明 | 十三条入口分别试旧参数。四个平台测试省略与显式声明、互斥值。小红书两帖型分别选 AI；Rednote 复用已有两帖型样本。TikTok 两帖型各测关闭时入口缺失、以及开关仍为开。Instagram 仅传 `--no-ai-generated` 复现上表各状态 | 用法错误退出 `2` 且未上传。省略保留预设值。只传 AI 的遮挡场景也须退出 `1`、Share 零点击。可继续的默认关闭与已读到关闭能从输出区分 |
| 2. 帖子地点 | 八条入口各验一次成功、一次无同名候选。成功例覆盖近似名排在前、两个同名异址、大小写和多余空白。受控编辑器补入口缺失、资格提示、列表未收起和终值不符。Instagram 增加名称与地址分行的候选 | 成功结果能还原点了哪一行和收起后的名称；每个失败分支均指出原因并停在发布前。空白参数在上传前被拒绝 |
| 3. 配文与关联 | 六个编辑器各验普通同名、同名「新建话题」或 `Add` 的点选与发布前回读，另用只有近似项的场景验文字降级。混入重复词、链接片段、紧邻标点和换行。覆盖关联数超限、全文被改写、选错词、整帖硬限制 | 六处特殊候选都能在原位读回同名关联及完整配文才交付。逐词结果与原稿顺序对应，允许的文字降级保留全文。错词、改稿及整帖硬限制均阻止提交 |
| 4. 迁移与结果兼容 | 核对 Instagram、Facebook 两类发布目标的两种帖型及 YouTube 简介。预填后台关键词，在配文中写入公开话题，并在 YouTube 独立标题中放另一个话题。读取 Instagram 默认及自定义结果文件，以及另三平台的终端结果 | 公开配文与预期逐字一致，标题和后台关键词符合各自输入。Instagram 不发布模式成功为 `prepared`，现有结果消费者仍能识别原选项及顶层状态 |

沿用 Instagram 选项测试中经命令入口检查上传前退出码的做法，用已有 Instagram 配文页、TikTok Studio 与小红书编辑器样例复现页面状态。已有不发布模式覆盖 Share 就绪和停止点。上述测试覆盖命令解析、请求校验、平台编辑器和结果输出。[Instagram 选项测试](../../tests/test_instagram_options.py) · [Instagram 不发布模式测试](../../tests/test_instagram_no_publish.py) · [TikTok 图片帖命令测试](../../tests/test_tiktok_note_cli.py) · [小红书话题测试](../../tests/test_xhs_topics.py)

## Out of Scope

- YouTube、Facebook 个人主页、Facebook Page 的 AI 声明、地点、签到和独立关键词功能开发。这五条命令在本规格内承担旧参数移除与公开配文迁移。
- 新增平台或帖型、移动端专属操作、发布后编辑、API 补标，以及平台自动添加 AI 标识的判定。
- 跨账号、地区或界面语言的普遍可用性承诺。后续若在同一帖型观察到两个账号的控件不同，保留两份页面证据，再决定该变体的补验范围。
