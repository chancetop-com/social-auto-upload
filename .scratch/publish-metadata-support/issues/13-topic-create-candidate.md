# 遇到同名的「新建话题」或 Add 候选时，发布命令应该点选还是保留文字？

Type: grilling
Label: wayfinder:grilling
Status: resolved
Blocked by: 12

## Question

当作者写了一个话题，唯一同名行在小红书或 Rednote 标为「新建话题」，或在 TikTok 标为 `Add` 时，是否应主动点选？分别确定两种界面下的预期动作、确认关联所需的回读，以及跳过时给调用方的原因。TikTok 的 `Add` 是实测行文案，其创建语义尚未验证。

沿用已经确定的配文全文与逐词回读口径。[各平台的标签写到哪里，什么结果算设置成功？](05-tags-native-and-fallback.md#answer) · [小红书、Rednote 和 TikTok 怎样在发布前区分已关联的话题和普通文字？](12-inline-topic-readback.md#answer)

## Answer

2026-11-20，操作者确认小红书、Rednote 和 TikTok 的视频与图文入口统一按话题名称选择候选。只要有同名选项就点选，包括标为「新建话题」或 `Add` 的行。只有找不到同名选项时才在原位置保留 `#话题` 文字，逐词结果注明「无同名候选」。例如，输入 `#coffee` 时，列表里只有 `#coffeecreamer` 也按无同名候选处理。

点选后沿用同一套回读口径。小红书和 Rednote 从正文的话题锚点读取名称，TikTok 从正文的话题标记读取名称。名称与原词一致才报告「已关联」，发布前还须核对配文全文的顺序、文字和标点。现有样本验证了普通同名行点选后的关联，以及跳过「新建话题」或 `Add` 后的文字状态。这两种行点选后的结果仍待实测。[发布前逐词回读记录](12-inline-topic-readback.md#answer)
